## 0. 먼저 — 체험 서버와 오픈소스는 **다른 것**이다

| | 오픈소스 저장소 | 공개 체험 서버 |
|---|---|---|
| 무엇 | 코드. 누구나 받아 자기 서버에 올린다 | 우리가 띄워 둔 서버 한 대 |
| 제한 | **없다** | 체험 계정은 내려받기 금지 · 주기적 정리 |
| 비용 | 0원 | 서버 비용 + 관리 |

🔴 **코드에 제한을 박아 두는 것은 뜻이 없다.** 소스가 공개돼 있으니 `DEMO_MODE`를 끄거나
`apps/api/src/demo.ts`를 지우면 그만이다. 제한이 실제로 서는 자리는 **우리가 띄운 서버뿐**이고,
거기서도 목적은 「약 올려 가입시키기」가 아니라 **공개 모래밭을 운영하는 최소한의 안전장치**다.

받아서 자기 서버에 올리는 사람에게 제한을 걸면, 그 사람은 그냥 안 쓴다.
오픈소스의 목적이 확산이라면 **제한은 체험 서버에만** 둔다.

## 1. 체험 서버 구성 — 환경변수 넷이면 된다

```bash
DEMO_MODE=on                  # 체험판으로 띄운다
AAS_DEMO_LOGIN=admin          # 생략하면 admin
AAS_DEMO_PASSWORD=1234        # 생략하면 1234
AAS_DEMO_RESET_MINUTES=60     # 방문자가 60분 넘게 안 쓴 파일을 지운다 (0이면 안 지움)
AAS_SIGNUP=on                 # 체험판이면 자동으로 켜진다
AAS_SIGNUP_ROLE=editor        # 가입한 사람의 역할 (viewer / editor) — 🔴 admin은 받지 않는다(가입하면 누구나 관리자가 된다)
```

켜면 이렇게 동작한다.

| | 체험 계정(admin/1234) | 가입한 계정 |
|---|---|---|
| 열기·고치기·검사·자동 고치기 | ✅ | ✅ |
| 검증 결과서 **보기** | ✅ | ✅ |
| AASX·번들·첨부 **내려받기** | 🔒 막힘 | ✅ |

### 작업 공간은 로그인마다 따로다

체험 계정은 **여럿이 같이 쓰는 한 계정**이다. 계정으로 가르면 모두가 한 칸에 들어가
A가 올린 설비 AASX를 B가 그대로 본다 — 도면·운전 데이터·제조사명이 든 파일이 올라오는 도구다.
그래서 **로그인마다** 작업 공간을 따로 준다.

| 누구 | 보는 것 |
|---|---|
| 체험 계정으로 들어온 방문자 | **이번 로그인에서** 자기가 올린 것 + 함께 쓰는 파일(템플릿, 읽기 전용) |
| 가입한 사람 | 자기 계정으로 올린 것 — 다시 로그인해도 그대로 |
| 관리자 · API 키 | 전부 |

- 남의 파일은 **없는 것처럼** 보인다. 주소를 알아도 404이고, 진짜 없는 파일과 답이 같다
- 방문자가 `AAS_DEMO_RESET_MINUTES`(기본 60분) 넘게 손대지 않은 파일은 지운다.
  **가입한 사람의 파일은 지우지 않는다**
- 🔴 체험 계정은 **로그인을 새로 하면 빈 칸에서 시작한다.** 로그인이 곧 작업 공간이라,
  로그아웃하거나 8시간 안 써서 풀리면 먼저 올린 것은 다시 보이지 않는다(곧 지워진다).
  화면의 띠가 그렇게 알린다. 계속 쓰려면 가입하게 된다
- 🔴 **운영자는 전부 본다.** 숨기는 대상은 다른 방문자이지 서버 주인이 아니다.
  처리방침에 그렇게 적을 것

막는 자리는 저장소다. 주소의 파일 번호만 지키면, 파일을 가로지르는 길(계층에 다른 파일
잇기 · 다른 파일에서 가져오기 · 번들 · 레지스트리)로 샌다 — 그 길들도 시험으로 묶어 두었다.

## 2. 서버 — 네 가지 길

가장 싼 것부터. 체험 서버 한 대 기준이다.

| 길 | 월 비용 | 받는 것 | 걸리는 것 |
|---|---|---|---|
| **① 사내 PC + 터널**(Cloudflare Tunnel) | **0원** | 공인 도메인·HTTPS까지 자동 | PC가 꺼지면 내려간다. 사내망이 뚫리는 통로가 된다 |
| **② 무료 티어 VM**(Oracle Cloud Always Free 등) | **0원** | 진짜 서버 | 가입·카드 등록이 번거롭고, 정책이 바뀌면 끊긴다 |
| **③ 클라우드 VM**(네이버클라우드·AWS Lightsail) | **1~3만원** | 안정적. 국내 리전 | 직접 관리(업데이트·백업) |
| **④ PaaS**(Fly.io·Railway·Render) | **$5~** | 배포가 `git push` 수준 | DB가 따로 과금. 국외 리전 |

**권장: ③ 국내 클라우드 VM 1대.** 이유는 둘이다 — 국내 사용자 대상이라 응답이 빠르고,
회원가입으로 **개인정보를 받게 되면** 국외 이전이 또 하나의 절차가 된다(아래 4장).

사양은 **2코어 / 4GB / 40GB**면 넉넉하다. AASX는 수 MB이고 동시 접속이 수십이다.

## 3. 올리는 절차 — 다섯 단계

### ① 서버와 도메인

```bash
# VM을 만들고 접속한 뒤
sudo apt update && sudo apt install -y docker.io docker-compose-plugin
```

도메인은 하나 필요하다(`aas.회사도메인` 같은 하위 도메인이면 충분). A 레코드를 VM의 IP로.

### ② 코드와 설정

```bash
git clone <저장소> && cd AAS_Basyx
cp .env.example .env
```

`.env`를 이렇게 채운다.

```bash
POSTGRES_PASSWORD=긴-무작위-문자열      # 🔴 비우면 뜨지 않는다
APP_PORT=8080
AAS_ALLOW_OPEN=1
AAS_PUBLIC_URL=https://aas.회사도메인

DEMO_MODE=on
AAS_DEMO_RESET_MINUTES=60
AAS_SIGNUP_ROLE=editor
AAS_SETUP_CODE=아무도-모를-값          # 첫 관리자 선점 방지
```

### ③ 띄우기

```bash
docker compose up -d --build
docker compose logs -f app        # 🔑 설치 코드와 체험 계정이 여기 찍힌다
```

### ④ HTTPS — 🔴 **생략하면 안 된다**

회원가입을 받는 순간 **비밀번호가 평문으로 지나간다.** Caddy 한 장이면 인증서까지 자동이다.

```bash
cp Caddyfile.example Caddyfile    # 도메인만 자기 것으로 고친다
caddy run --config Caddyfile
```

그리고 `docker-compose.yml`의 포트를 `127.0.0.1:8080:8080`으로 묶어, 프록시를 거치지 않고는
못 들어오게 한다. nginx를 쓴다면 `Host`·`X-Forwarded-Proto`를 꼭 넘긴다([설치.md](설치.md)).

### ⑤ 관리자 계정 만들기 — 🔴 **체험판을 켜기 전에**

「첫 관리자 만들기」는 **계정이 하나도 없을 때만** 나온다. 체험판을 먼저 켜면 체험 계정이
생겨 버려서 그 화면이 안 나온다. 그래서 순서가 있다.

1. `.env`에서 `DEMO_MODE`를 **비워 둔 채** 띄운다
2. 브라우저 → **설정 → 첫 관리자 만들기** (③에서 찍힌 설치 코드를 넣는다)
3. `.env`에 `DEMO_MODE=on`을 넣고 `docker compose up -d`로 다시 띄운다
4. 그때 체험 계정(admin/1234)이 생긴다

이 관리자 계정으로 **설정 → 계정 관리**에서 가입한 사람들을 본다.
(이미 체험판으로 띄워 버렸다면 `.env`에 `AAS_TOKEN`을 넣고 다시 띄운 뒤
`POST /auth/users`를 그 키로 불러 관리자를 만든다.)

## 4. 🔴 회원가입을 받으면 생기는 의무 — 서버보다 이쪽이 더 걸린다

이름·연락처를 받는 순간 **개인정보 처리자**가 된다. 한국에서 최소한 다음이 따라온다.

| 항목 | 내용 |
|---|---|
| **개인정보처리방침** | 무엇을·왜 받고·얼마나 보관하고·언제 파기하는지 공개 |
| **수집·이용 동의** | 가입 화면에서 받는다(체크박스). 지금 화면에는 **없다** — 넣어야 한다 |
| **보관기간·파기** | "탈퇴 시 즉시" 같은 기준을 정하고 지킨다 |
| **열람·삭제 요구** | 요청하면 보여 주고 지워야 한다. 지금 화면에는 **탈퇴 기능이 없다** |
| **안전조치** | 비밀번호 해시(✅ scrypt) · 전송 암호화(HTTPS) · 접근 기록 |

구현해 둔 것: 동의 체크박스 ✅ · 탈퇴 ✅ · 방침 없으면 수집 안 함 ✅ ·
연락처 선택 ✅ · 확인 메일 안 보냄(명시) ✅.
**남은 것은 처리방침 문서 자체**다 — 그건 사람이 써서 올려야 한다.

**가장 싼 길은 「적게 받는 것」이다.** 지금 구현은 그 방향으로 맞춰 두었다.

- 연락처(이메일)는 **선택**이다. 비워도 가입된다
- 🔴 **`AAS_PRIVACY_URL`을 설정하지 않으면 연락처를 아예 받지 않는다.** 화면에 칸이
  나오지 않고, 보내도 서버가 거절한다. 어떻게 쓰는지 밝히지 않고 개인정보를 모으지
  않겠다는 뜻이고, 방침을 먼저 올리게 만드는 장치이기도 하다
- 연락처를 적으면 **동의 체크박스**가 나오고, 체크해야 가입된다
- 🔴 **확인 메일을 보내지 않는다.** 메일 서버가 없고, 흉내만 내면 「확인된 주소」라고
  믿게 만들어 더 나쁘다. 화면에도 그렇게 적어 두었다
- 이름·전화번호·회사는 **받지 않는다**
- **탈퇴**가 있다(설정 → 탈퇴). 잠그는 것이 아니라 계정과 연락처를 **지운다**.
  올린 파일과 변경 이력은 남는다 — 이력의 「누가」는 사람 표를 참조하지 않고 그때의
  이름을 베껴 둔 값이라, 계정을 지워도 「무슨 일이 있었나」는 지켜진다

> **연락처조차 안 받는 선택**도 있다. 로그인 이름과 비밀번호만 받으면 개인정보로 보기
> 어려운 쪽에 가깝고, 의무가 크게 준다. 다만 비밀번호를 잊은 사람을 도울 방법이 없어진다.
> 🔴 이것은 **사업 판단**이다 — 리드(잠재고객 명단)가 목적이면 받아야 하고, 체험만
> 시키는 것이 목적이면 안 받는 편이 낫다. 정해 주면 그대로 맞춘다.

법적 판단이 필요한 부분은 사내에서 확인할 것. 이 문서는 **무엇을 준비해야 하는지의 목록**이지
법률 자문이 아니다.

## 5. 올린 뒤 — 챙길 것

| 주기 | 할 일 |
|---|---|
| 배포할 때마다 | `git pull && docker compose up -d --build` |
| 매일(자동) | DB 백업 — `docker compose exec db pg_dump -U aas aas > 백업.sql` |
| 가끔 | `docker compose logs app`에서 오류·가입 추이 확인 |
| 가입 폭주 | 주소당 5건/시간 · 서버 전체 30건/시간으로 막는다. 그래도 몰리면 `AAS_SIGNUP=off`가 차단기다 |

### 남은 구멍 — 알고 띄울 것

1. **체험 계정은 로그인을 새로 하면 빈 칸에서 시작한다**(1장) — 이어서 쓰려면 가입해야 한다
2. **운영자는 방문자의 파일을 전부 본다** — 처리방침에 적어야 한다
3. **처리방침 문서는 사람이 써야 한다** — 프로그램은 「올려 뒀는지」만 확인한다
4. 메일을 보내지 않으므로 **비밀번호를 잊으면 관리자가 초기화**해 주는 수밖에 없다

막아 둔 것(2026-10-04 점검):
- ✅ **작업 공간을 로그인마다 가른다** — 같은 체험 계정으로 들어와도 서로의 파일을 못 본다
- ✅ OPC UA 노출은 **체험판에서 아예 뜨지 않는다**(인증 없는 포트라 공개 서버와 맞지 않는다)
- ✅ 체험 계정은 **자기 비밀번호를 못 바꾸고 탈퇴도 못 한다** — 하나가 바꾸면 그 뒤로
  아무도 못 들어왔다
- ✅ 가입 속도 제한(주소당 5건/시간 · 전체 30건/시간)
- ✅ 탈퇴 — 계정과 연락처를 지우되 감사 기록은 남는다

## 6. 요약 — 이 순서로 정하면 된다

1. **연락처를 받을 것인가** → 받으면 4장의 의무가 전부 따라온다
2. **서버를 어디에 둘 것인가** → 권장 ③ 국내 VM 1대(월 1~3만원)
3. 도메인 하나 + HTTPS(Caddy) → 1~2시간
4. `.env` 채우고 `docker compose up -d` → 30분
5. 공개
