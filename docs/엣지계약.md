# 엣지 계약 — `vexplor.edge/1`

*English: [edge-contract.md](edge-contract.md)*

공장 안에서는 작은 프로그램 하나 — **원격 수집기**(엣지)가 돕니다. PLC · 제어기 값을 읽어 밖으로 보냅니다. 이 문서는
그 프로그램이 상대하는 규격입니다. **서버 쪽은 두 제품이 똑같이 구현합니다** — VEXPLOR AAS Studio 와 VEXPLOR Logic
Studio Cloud. 그래서 엣지 프로그램은 하나로 두 제품에 붙습니다.

| | |
|---|---|
| 규격 | `vexplor.edge/1` |
| 끝점 | `POST /edge/v1/register`(한 번) · `GET /edge/v1/read-list` · `POST /edge/v1/batches` |
| 스키마 | [`docs/edge/schemas/`](edge/schemas/) — JSON Schema, 실제 예시는 [`docs/edge/examples/`](edge/examples/) |
| 전송 | HTTPS · JSON 본문 · UTF-8. 엣지가 밖으로 연결하고, 공장 안으로 들어오는 연결은 없습니다 |
| 신원 | 1회용 등록 코드 → 엣지가 Ed25519 키 쌍을 만들어 공개키를 등록 → 요청마다 서명 |
| 중복 방지 | (장치, `bootId`, `seq`) — 같은 묶음을 두 번 보내도 한 번만 저장됩니다 |

## 1. 원칙

1. **밖으로만.** 엣지가 서버로 HTTPS 연결을 엽니다(443, 필요하면 HTTP `CONNECT` 프록시 경유). 서버는 엣지나 공장
   망으로 연결하지 않습니다.
2. **읽기만.** 엣지는 설비를 읽기만 하고 PLC 에 쓰지 않습니다. 규격에 명령 채널이 없고 **원격 정지도 없습니다** —
   서버가 할 수 있는 일은 (가) 읽을 목록 바꾸기(사람이 승인한 뒤에 적용) (나) 장치 해지(해지되면 엣지가 보내기를
   멈춤) 둘뿐입니다.
3. **엣지에는 AAS 해석기가 없습니다.** 서버가 AAS(AID — Asset Interfaces Description)를 읽어 「무엇을 어디서 읽을지」를
   평범한 목록으로 내려 줍니다. 엣지는 통신 규약만 알고 AAS 메타모델은 모릅니다.
4. **사람이 승인하기 전에는 읽지 않습니다.** 새 장치나 바뀐 목록은, 서버에서 누군가 태그를 승인할 때까지 빈 목록을
   받습니다.
5. **수집값을 AAS 에 써 넣지 않습니다.** 값은 서버의 값 저장소에 두고, AAS 에는 인터페이스 설명과 참조만 둡니다.
6. **끝에 더하기만.** `/1` 안에서는 필드를 더하기만 합니다. 양쪽 다 모르는 필드는 무시합니다. 그 밖의 변경은 새
   규격(`vexplor.edge/2`, 새 경로 `/edge/v2/…`)이고, 서버는 `/1` 을 적어도 한 릴리스 동안 유지합니다.

## 2. 요청마다 서명

모든 요청에 헤더 네 개를 붙입니다.

| 헤더 | 값 |
|---|---|
| `X-Edge-Device` | 등록 때 받은 `deviceId`. 등록 요청 자체에는 글자 그대로 `register` |
| `X-Edge-Timestamp` | 유닉스 시각(초). 서버 시계와 ±300초 안이어야 받습니다 |
| `X-Edge-Nonce` | 16바이트 이상 난수, base64url. 같은 장치가 10분 안에 다시 쓰지 않습니다 |
| `X-Edge-Signature` | `ed25519=` + 64바이트 서명의 base64url(채움 문자 없음) |

서명할 글은 일곱 줄을 `\n` 으로 이은 것입니다(마지막 줄바꿈 없음, UTF-8).

```
vexplor.edge/1
<메서드, 대문자>
<보낸 그대로의 경로와 쿼리, 예: /edge/v1/read-list>
<X-Edge-Timestamp>
<X-Edge-Nonce>
<X-Edge-Device>
<본문 바이트의 SHA-256, 소문자 16진수 — GET 은 빈 문자열의 값>
```

첫 줄은 규격 이름입니다. TLS 세션이 아니라 경로와 본문 해시에 서명하므로, TLS 를 들여다보는 프록시를 지나도 서명이
깨지지 않습니다. 등록 요청은 등록하려는 그 키로 서명합니다(엣지에 개인키가 있다는 증명).

**계산 예시**(RFC 8032 §7.1 시험 키 1 — 실제 장치에 쓰지 마십시오). 값은 영문판 표와 같습니다.

| | |
|---|---|
| 개인키 시드(16진수) | `9d61b19deffd5a60ba844af492ec2cc44449c5697b326919703bac031cae7f60` |
| 공개키(base64url) | `11qYAYKxCrfVS_7TyWQHOg7hcvPapiMlrwIaaPcHURo` |
| 요청 | `POST /edge/v1/batches`, 장치 `dev_8Q2K7M4N`, 시각 `1792141205`, 난수 `bm9uY2UtMDAwMDAwMDAwMQ` |
| 본문 | [`docs/edge/examples/signed-batch.body.json`](edge/examples/signed-batch.body.json)(바이트 그대로, 마지막 줄바꿈 없음) |
| 본문 SHA-256 | `c0d5d9913f729fa8d4893e7f6c30fd2e665d42559f84642514365e0955427651` |
| `X-Edge-Signature` | `ed25519=vEOC6NvXN1SGvT7EJPnqD1O4ji89dr-Uk1UVaUqO94fX5-RVDpwhEwnAW2dVXAkRSztL_kHUP7LgTvQL1LwiCA` |

## 3. 등록 — `POST /edge/v1/register`

서버에서 사람이 **등록 코드**를 만듭니다(작업 공간 하나에 속하고, 한 번만 쓰이며, 서버가 따로 정하지 않으면 24시간 뒤
만료). 엣지를 그 코드로 설치하면, 엣지가 Ed25519 키 쌍을 스스로 만들어 개인키는 그 PC 에 두고 다음을 보냅니다.

요청 `vexplor.edge.register/1` — `code`, `publicKey`(32바이트 원본, base64url), `device`(`name`, 선택 `hostname`,
`software` `{name, version}`). 응답 **201** `vexplor.edge.registration/1` — `deviceId`, `registeredAt`, `server`(`tool`,
`version`, `contract`), `limits`, `readList`(`path`, `pollSeconds`).

장치는 코드가 속한 작업 공간에만 속하고 다른 것은 보지 못합니다. 모르는 코드 · 이미 쓴 코드 · 만료된 코드는 모두 401
`RegistrationCodeInvalid` 로 답합니다(어느 경우인지 밝히지 않습니다). 같은 공개키는 두 번 등록되지 않습니다(409
`KeyAlreadyRegistered`).

## 4. 읽을 목록 — `GET /edge/v1/read-list`

서버가 AAS 에서 이미 풀어 놓은 「무엇을 읽을지」입니다. 응답 **200** `vexplor.edge.readList/1`.

- `revision` — 뜻 없는 문자열이며 목록이 바뀔 때마다 바뀝니다. `If-None-Match: "<revision>"` 으로 보내면 바뀐 것이
  없을 때 **304** 를 받습니다. 응답 `ETag` 에도 같은 값이 있습니다.
- `state` — `pending-approval`(아직 승인 없음: `interfaces` 빔) · `approved` · `paused`(승인했다가 사람이 멈춤:
  `interfaces` 빔, 엣지는 읽기를 멈춤).
- `pollSeconds` — 다시 묻기까지 기다릴 시간(묶음 응답의 `readListRevision` 이 다르면 더 일찍 물어도 됩니다).
- `interfaces[]` — 설비 연결 하나마다: `interfaceId`, `packageId`, `aasId`, `globalAssetId`, `interfaceName`(AID
  인터페이스), `protocol`(`OPCUA` · `MODBUS` · `MQTT` · `HTTP`), `endpoint`(AID `base`), `security`, `intervalMs`,
  `tags[]` — `tagId`, `propertyName`, `address`(AID `href`), 선택 `key` · `type` · `unit`, `fields`(나머지 AID form
  필드, 이름별 글자), 그 태그만 인터페이스 주기 대신 쓰는 선택 `intervalMs`.
- `security` — `mode`(OPC UA 는 `None` · `Sign` · `SignAndEncrypt`, 그 밖은 `None` · `TLS`), 선택 `policy`, 선택
  `credentialRef`. **목록에는 비밀번호도 키도 들어가지 않습니다.** `credentialRef` 는 설치하는 사람이 엣지 PC 에 저장해
  둔 자격 증명의 이름이고, 엣지가 그 PC 에서 찾아 사용합니다.

엣지가 지원하지 않는 통신 규약의 인터페이스는 건너뛰고, 다음 묶음의 `status` 에 알립니다.

### 4.1 태그 힌트 (2.5.0 에서 추가 — 선택 · 참고용)

태그마다 힌트 세 가지가 붙을 수 있습니다. 승인 전에 사람에게 목록을 보여 주는 받는 쪽을 위한 것입니다
(`@aas/bundle` 의 `aidReadList` 로 읽을 목록을 직접 만드는 다른 제품도 같은 값을 받습니다).

- `semanticId` — 그 태그 값이 속한 모델 요소의 semanticId(실시간 겹쳐 보기 · 실행 이벤트와 같은 규칙으로 찾습니다).
  속성이 요소를 하나도 찾지 못하거나 둘 이상 찾으면 넣지 않습니다.
- `suggestedRole` — `run_state` · `counter` · `alarm_source` · `meter` · `condition` · `quality` · `value`. semanticId 표
  (`apps/api/src/edge/tag-hints.ts`, 정확히 같을 때만)에서 정합니다. 표에 없는 semanticId 는 `value` 입니다.
- `limits[]` — `{ bound: "usl" | "lsl", value, semanticId, source }`. 같은 파일에서 이 값의 한계를 정하는 속성입니다
  (예: `SettingForce` 에 TechnicalData `MaxSettingForce`). 한 값에 여러 개(성능 한계 · 안전 한계)가 있으면 모두
  `source`(`<서브모델 idShort>:<idShortPath>`)와 함께 넣습니다.

힌트는 **`revision` 에 들어가지 않습니다.** 서버를 올려 힌트가 늘거나 바뀌어도 현장에 다시 승인을 묻지 않고, 엣지가
다시 시작하지도 않습니다. 엣지는 힌트를 무시합니다. 역할과 한계는 사람이 확인합니다 — 힌트 혼자 정하는 것은 없습니다.

## 5. 값 묶음 — `POST /edge/v1/batches`

요청 `vexplor.edge.batch/1`.

- `bootId` — 엣지 프로세스가 시작할 때마다 새로 만드는 UUID.
- `seq` — 1부터, 한 부팅 안에서 새 묶음마다 1씩 증가. **(장치, `bootId`, `seq`) 가 중복 방지 키입니다.**
- `readListRevision` — 값을 읽을 때 쓴 목록.
- `createdAt`, `samples[]` — `tagId`, `observedAt`(설비가 준 시각, 없으면 읽은 시각), `receivedAt`(엣지가 읽은 시각),
  `value`(숫자 · 글자 · 참거짓 · null), 선택 `quality` · `error`.
- 선택 `status` — `startedAt`, `queuedBatches`, `droppedBatches`, `software`, 인터페이스별 `connected` · `lastError`.
  값이 없는 묶음은 살아 있다는 신호로 쓸 수 있습니다.

응답 **200** `vexplor.edge.batchResult/1` — `bootId`, `seq`, `accepted`, `duplicate`, `rejected[]`(`index`, `tagId`,
`code` — 예: 승인된 목록에 없는 태그), 서버의 현재 `readListRevision`.

`rejected[].code` 는 값 하나를 저장하지 않은 이유입니다: `NotApproved`(아직 승인 없음) · `UnknownTag`(승인된 목록에 없음) ·
`PackageUnavailable`(파일이 없어졌거나 더 이상 그 장치의 것이 아님) · `BadTime` · `TooLong` · `TypeMismatch`(예: `float`
태그에 글자). 묶음의 나머지 값은 저장되며, 거절된 값은 다시 보내지 않습니다.

이미 받은 묶음은 200 · `duplicate: true` 로 답하고 다시 저장하지 않습니다. 서버는 `seq` 가 순서대로나 빠짐없이 오기를
요구하지 않습니다.

**순서.** 엣지는 묶음을 한 번에 하나씩, 오래된 것부터 보내고, 앞 묶음의 답을 받은 뒤에야 다음 묶음을 보냅니다 — 끊겼다
돌아오면 밀린 묶음이 그 뒤에 읽은 묶음보다 먼저 도착합니다. 받는 쪽은 같은 장치에서 마지막으로 저장한 것보다 오래된 묶음을
시계 오류가 아니라 밀린 묶음으로 다뤄도 됩니다.

## 6. 상한 · 오류 · 엣지가 할 일

상한은 등록 응답(`limits`)으로 오고, 서버가 언제든 낮출 수 있습니다 — 그러면 413 이나 429 로 답합니다. 기본값은 장치마다
`maxBatchBytes` 1 048 576 · `maxSamplesPerBatch` 5 000 · `requestsPerMinute` 60.

오류는 한 가지 모양 `vexplor.edge.error/1` 로 답합니다 — `code`, `message`, `retryable`, 선택 `retryAfterSeconds`.

| 상태 | `code` | 엣지가 할 일 |
|---|---|---|
| 400 / 422 | `BadRequest` · `SchemaMismatch` | 그 묶음은 로컬 「거절됨」 폴더에 두고 다시 보내지 않으며 다음 묶음으로 넘어갑니다 |
| 401 | `SignatureInvalid` · `UnknownDevice` | 보내기를 멈추고 대기열은 지키며 로컬 경보를 냅니다. 스스로 다시 등록하지 않습니다 |
| 401 | `ClockSkew` | 시계를 확인한 뒤 다시 보냅니다(서버 `Date` 헤더를 기록) |
| 401 | `RegistrationCodeInvalid` | 등록 때만 — 설치하는 사람에게 새 코드를 요청합니다 |
| 403 | `DeviceRevoked` | 보내기를 멈추고 대기열은 지키며 로컬 경보를 냅니다 |
| 409 | `KeyAlreadyRegistered` | 등록 때만 — 키 쌍을 새로 만들고 새 코드를 요청합니다 |
| 413 | `PayloadTooLarge` | 값을 새 묶음들로 나눠(새 `seq`) 보내고, 원래 묶음은 「거절됨」에 둡니다 |
| 429 · 503 | `RateLimited` · `Unavailable` | `Retry-After`(초)만큼 기다렸다가 **같은** 묶음을 다시 보냅니다 |
| 5xx · 네트워크 · 시간 초과 | `ServerError` | **같은** 묶음을 간격을 늘려 다시 보냅니다: 1초부터 두 배씩 5분까지, ±20% 흔들기 |
| 그 밖의 상태(404, 405 …) | — | 5xx 와 같이 같은 묶음을 간격을 늘려 다시 보내고 기록합니다. 엣지를 멈추는 것은 401(`ClockSkew` 제외)과 403 뿐입니다 — 다른 답은 중간의 무엇(프록시 · 업그레이드 중인 서버)에서 옵니다 |

**로컬 대기열.** 모든 묶음은 보내기 전에 디스크에 쓰고, 2xx 를 받은 뒤에만 지웁니다. 대기열이 정한 크기에 이르면 가장
오래된 묶음부터 버리고 버린 수를 `status.droppedBatches` 에 남깁니다 — 소리 없이 버리지 않습니다.

**묶음이 기다리는 기간.** 보내지 못한 묶음은 최대 `maxQueueDays`(엣지 설정, 기본 30일) 동안 둡니다. 그보다 오래된 것은
같은 방식으로 버리고 그 수를 남깁니다. 받는 쪽은 중복 방지 기억(§5 의 키)을 **그보다 길게** 지켜, 오래 끊겼다 다시 보낸
묶음도 중복으로 알아보게 합니다.

## 7. 네트워크

- HTTPS 만. 엣지는 `http://` 서버 주소를 받지 않습니다 — 같은 PC(루프백, 시험용)만 예외입니다.
- 프록시: `HTTPS_PROXY` 또는 설정 · HTTP `CONNECT` · TLS 는 끝에서 끝까지. 허용 목록은 IP 주소가 아니라 서버 호스트
  이름으로 거십시오.
- 밖으로 나가는 목적지는 서버 기본 주소 하나입니다(업데이트 받는 곳은 이 규격 밖).

## 8. AAS Studio 서버 쪽

기본은 꺼져 있습니다. `EDGE=on` 으로 켭니다(데모에서는 켜지지 않음). 서버 상태를 저장하는 저장소가 필요하며 메모리 · 폴더 ·
PostgreSQL 모두 됩니다. 내려 주는 읽기 주기는 `COLLECT_INTERVAL` 이 있으면 그 값, 없으면 5초입니다.

| 사람용(로그인 또는 API 키) | |
|---|---|
| `POST /edge/registration-codes` | 호출한 사람의 작업 공간용 1회용 코드 — 한 번만 보여 주고 24시간 유효 |
| `GET /edge/devices` | 작업 공간의 장치. 승인 뒤 파일이 바뀌었으면 `changedSinceApproval` |
| `GET /edge/devices/:deviceId/read-list-preview` | 지금 승인하면 내줄 목록과 그 `revision` |
| `POST /edge/devices/:deviceId/approve` `{ revision, intervals? }` | 미리 본 목록 그대로 승인. 그사이 파일이 바뀌었으면 거절(409). `intervals` `{ <interfaceId 또는 tagId>: 밀리초 }`(100ms~1시간)로 읽기 주기를 정하며, 주기만 바꿔 다시 승인해도 엣지는 새 revision 을 받습니다 |
| `POST /edge/devices/:deviceId/pause` · `/revoke` | 이후 빈 목록 · 이후 장치 거절 |

장치는 코드를 만든 사람의 작업 공간에 속하고, 관리자가 승인해도 다른 작업 공간은 보지 못합니다. 목록에는 그 작업 공간이
소유한 파일만 들어갑니다(공유 파일은 읽을 수는 있어도 값을 받을 수 없습니다). 작업 공간을 나누는 서버에서는 나누기 전에
등록된 장치를 다시 등록할 때까지 거절합니다. 등록 시도는 주소마다 분당 10번, 서버 전체 분당 120번까지입니다. 목록이 바뀌면 다시 승인할
때까지 새 목록을 내주지 않습니다. 기준 클라이언트는 모의 엣지 `scripts/mock-edge.mjs` 입니다
(`node scripts/mock-edge.mjs --server https://… --code …`).

## 9. 이 규격이 주장하지 않는 것

VEXPLOR 의 규격이지 IDTA 표준이 아닙니다. 읽을 목록은 AID(IDTA-02017) 서브모델에서 만들지만, 이 규격을 지원한다고
AID 를 전부 지원하는 것은 아닙니다 — 서버가 풀지 못하는 통신 규약과 form 필드는 목록에서 빠집니다.
