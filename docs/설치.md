# 설치 안내서 (서버 관리자용)

[English](install.md) · **한국어**

> 쓰는 사람용 매뉴얼은 [사용법.md](사용법.md)입니다. 이 문서는 **서버에 올리는 사람**을 위한 것입니다.

## 무엇이 필요한가

| 항목 | 최소 | 권장 |
|---|---|---|
| 운영체제 | Docker가 도는 것이면 무엇이든 (Linux · Windows · macOS) | Linux 서버 |
| Docker | Docker Engine 20 이상 + Compose v2 | 최신 |
| 메모리 | 4 GB | 8 GB |
| 디스크 | 10 GB | 50 GB (AASX와 수집값이 쌓입니다) |
| 인터넷 | **필요 없음** — 배포 꾸러미에 이미지가 들어 있습니다 | |

## 배포 꾸러미는 **CPU가 다른 두 벌**입니다

| 꾸러미 | 대상 | 안에 든 이미지 |
|---|---|---|
| `VEXPLOR-AAS-Studio-<판번호>-windows.tar.gz` | 윈도우 PC·서버, 인텔/AMD 리눅스 | `linux/amd64` |
| `VEXPLOR-AAS-Studio-<판번호>-mac.tar.gz` | 애플 실리콘 맥(M1 이상), ARM 리눅스 | `linux/arm64` |

🔴 **바꿔 쓰면 뜨지 않습니다.** 받는 쪽 컴퓨터에 맞는 것을 주십시오.

## 설치 — 세 단계

꾸러미를 풀고, 안에 든 설치 파일을 **두 번 클릭**합니다.

| | 윈도우 | 맥 |
|---|---|---|
| ① 설치 | `설치.bat` | `설치.command` |
| ② 다시 시작 | `실행.bat` | `실행.command` |
| ③ 내리기 | `중지.bat` | `중지.command` |

리눅스 서버라면 터미널에서:

```bash
tar xzf VEXPLOR-AAS-Studio-2.4.0-windows.tar.gz
cd VEXPLOR-AAS-Studio-2.4.0-windows
cp .env.example .env      # ① 설정 파일을 만듭니다
# .env를 열어 POSTGRES_PASSWORD를 채웁니다  ← ②
docker load -i images.tar.gz && docker compose up -d   # ③
```

끝나면 `http://<서버주소>:8080` 으로 접속됩니다.

## .env — 반드시 채워야 하는 것은 **하나**입니다

```bash
POSTGRES_PASSWORD=긴-무작위-문자열     # 🔴 비우면 뜨지 않습니다
```

접근 제어는 **선택**입니다. 기본은 **잠그지 않는 것**입니다 —
사내에서 누구나 열고 고쳐도 되는 것이 이 도구의 기본 쓰임새이기 때문입니다.

```bash
AAS_ALLOW_OPEN=1                      # 토큰 없이 사내에 연다 (설치 스크립트가 넣어 줍니다)
AAS_TOKEN=                            # 기계용 API 키. 비움 = 누구나 / 채우면 그 키를 가진 것만
AAS_READONLY_TOKEN=                   # 보기만 되는 키(선택)
AAS_SETUP_CODE=                       # 첫 관리자 선점 방지. 비우면 기동 로그에 무작위로 찍힙니다
AAS_LANG=                             # 기동 로그의 언어. en = 영어, 비움 = 한국어
```

### 사람에게는 **계정 로그인**을 쓰십시오 (권장)

올려 두고 브라우저로 들어가 **설정 → 첫 관리자 만들기**를 누르면 그때부터 계정으로 씁니다.
관리자/편집자/열람자 세 역할이 있고, **누가 고쳤는지가 변경 이력에 남습니다.**
자세한 것은 [사용법 §12](사용법.md).

🔑 밖으로 열린 서버에서는 첫 관리자를 만들 때 **설치 코드**를 묻습니다. 기동 로그에서 찾으십시오:

```bash
docker compose logs app | grep "설치 코드"
#   🔑 첫 관리자 설치 코드: 3f9a1c2e7b04
```

기동 로그를 영어로 찍게 했다면(`AAS_LANG=en`) `grep "setup code"`로 찾습니다.

🔴 이것이 없으면 같은 망의 **아무나 먼저 눌러 관리자가 되고** 담당자가 막힙니다.
미리 정해 두려면 `.env`의 `AAS_SETUP_CODE`에 값을 적으십시오.

🔴 **사람이 로그인을 쓰기 시작하면 HTTPS를 두십시오.** 평문으로는 비밀번호와 로그인
쿠키가 그대로 지나갑니다. 설정 예시는 아래 「인터넷에 열 때」와 사용법 §12-3.

### 잠그고 싶을 때만 읽으십시오

`AAS_TOKEN`에 값을 넣고 다시 띄우면 그때부터 토큰을 가진 사람만 들어옵니다.
영문·숫자·기호로 **20자 이상**을 권합니다 — HTTP 헤더는 ASCII가 원칙이라 한글은 쓰지 마십시오.

🔴 **토큰도 없고 `AAS_ALLOW_OPEN=1`도 없으면** 프로그램이 스스로 안전장치로 들어가
그 컴퓨터에서만(`127.0.0.1`) 문을 엽니다. 도커로 띄웠다면 **아무도 접속하지 못합니다.**
설치 스크립트가 `AAS_ALLOW_OPEN=1`을 자동으로 넣어 주므로 보통은 신경 쓸 일이 없습니다.

기동 로그에 지금 어느 상태인지 한 줄로 찍힙니다 — 한 번 보십시오.

| 로그 | 뜻 |
|---|---|
| `🔓 토큰 없이 열었습니다` | 사내 누구나 씁니다 (설치 기본값) |
| `인증 켜짐 — 전체 토큰 n개` | 토큰을 가진 사람만 |
| `🔒 보호 모드` | 이 컴퓨터에서만 — 다른 데서 안 열립니다 |
| `🔑 첫 관리자 설치 코드: …` | 계정을 처음 만들 때 물어볼 값입니다. 계정이 생기면 쓰이지 않습니다 |

### 그 밖에 조절할 수 있는 것

| 항목 | 뜻 |
|---|---|
| `APP_PORT` | 밖으로 여는 포트(기본 8080) |
| `COLLECT` / `COLLECT_INTERVAL` | 현장 값 수집(OPC UA). 장비가 있을 때만 `on` + 주기(초) |
| `COLLECT_RETENTION_DAYS` | 수집값 **보존 기간(일)**. 그보다 오래된 값을 기동 때와 한 시간마다 지웁니다. `.env` 기본 180 · 비우거나 0이면 영구 보관. 모델(AASX)은 건드리지 않습니다 |
| `COLLECT_COMPRESS_AFTER_DAYS` | TimescaleDB Community Edition 일 때만 — 이 일수가 지난 수집값을 **압축**합니다(실측 15~22분의 1 — 태그 1 000개 · 1초 주기 1시간: 원본 1 099 MB, 압축 50 MB). 비우면 7 · 0 이면 압축 안 함 |
| `COLLECT_ROLLUPS` | TimescaleDB Community Edition 일 때만 — **1분 · 1시간 집계** `collected_value_1m` / `collected_value_1h`(속성별 평균 · 최소 · 최대 · 마지막 · 개수). 계속 갱신하고 35일 전까지 다시 반영해 원격 수집기가 늦게 보낸 값도 들어갑니다. 비우면 켜짐 · `off` 면 없음 |
| `COLLECT_ROLLUP_MINUTE_DAYS` | 1분 집계를 두는 기간. 비우면 90 · 0 이면 영구. 1시간 집계는 계속 둡니다 |
| `AAS_PUBLIC_URL` | 🔴 **리버스 프록시 뒤에 두면 반드시** 설정. 레지스트리가 이 주소를 알려 줍니다 |
| `CORS_ORIGIN` | 다른 주소의 **웹 앱**(사내 포털 등)이 브라우저에서 이 API를 부를 때 그 출처를 쉼표로. 비우면 교차 출처 요청을 브라우저가 막습니다(기본·가장 안전). 저작 화면은 같은 포트라 필요 없고, 서버끼리 부르는 것도 무관합니다 |
| `AAS_POLICY_FILE` | 규약(값)을 코드 수정 없이 바꾸는 파일 — 사용법 §10-4 |
| `LINT_STANDARD_TERMS` | 규정 충돌 ⑤ 선택 |
| `AASX_MAX_TOTAL_MB` | 업로드 AASX 해제 상한. 요청 본문 상한도 이 값을 따릅니다(이 값의 두 배, 최대 512 MB) |
| `OPCUA_SERVER` · `OPCUA_PORT` · `OPCUA_REFRESH` · `OPCUA_HOST` | 모아 온 값을 상위 앱(MES·SCADA)에 OPC UA로 내줍니다. 켤 때만 `on`. 포트 기본 4840 · 갱신 주기 기본 5초 · `OPCUA_HOST`는 다른 PC에 알려 줄 이 서버의 주소. 기본은 보안 모드입니다 — 클라이언트는 이 서버의 계정으로 로그인하고, 관리자가 클라이언트 인증서를 처음 한 번 신뢰해 줍니다([연동.md](연동.md) 9장). `OPCUA_ALLOW_INSECURE=on`이면 인증 없는 예전 포트로 돌아가니, 그때는 사내망 밖으로 열지 마십시오. 설비(PLC)도 대개 4840을 쓰므로 헷갈릴 자리면 4841처럼 다른 포트로 띄우십시오 |
| `AAS_WORKSPACE` | 비우면 팀이 같은 파일을 같이 봅니다(기본). `private`이면 저마다 자기가 올린 것만 봅니다. 관리자와 API 키는 전부 봅니다. 켜기 전에 올린 파일은 모두에게 읽기 전용으로 보입니다. 계정도 API 키도 없으면 첫 관리자를 만들기 전까지 파일 요청을 받지 않습니다 |
| `AAS_SIGNUP` · `AAS_SIGNUP_ROLE` · `AAS_PRIVACY_URL` | 스스로 가입하기와 그때 받을 역할, 개인정보처리방침 주소. **주의:** 사내망 서버에서는 `AAS_SIGNUP`을 비워 두십시오 — [배포_호스팅.md](배포_호스팅.md) §4 |
| `DEMO_MODE` 외 `AAS_DEMO_*` | 공개 체험 서버 구성 — [배포_호스팅.md](배포_호스팅.md) |
| `AAS_LANG` | **기동 로그의 언어.** `en`이면 영어, 비우면 한국어. Docker 구성도 `.env`에 적으면 그대로 적용됩니다. 서버 관리자가 보는 로그만 바뀝니다 — 쓰는 사람의 화면 언어는 브라우저마다 고르고, 고른 적이 없으면 브라우저 언어를 따릅니다(한국어 브라우저 → 한국어, 그 밖 → 영어). 지적 문구·오류처럼 서버가 만드는 글은 요청마다 그 요청이 청한 언어로 나갑니다 |
| `AAS_TEMPLATES_DIR` | **템플릿 폴더**. 여기 둔 `.aasx`가 기동 때 올라갑니다(Docker는 `./templates`). IDTA Content Hub에서 받은 공식 템플릿을 두면 「다른 파일에서 가져오기」에서 바로 고를 수 있습니다. 같은 파일명은 두 번 올리지 않고, 화면에서 지워도 다음 기동에 돌아옵니다 — 그만 쓰려면 폴더에서 빼십시오 |

## Docker 없이 띄우기 (Node.js)

배포 꾸러미 대신 소스에서 바로 띄울 수도 있습니다. **Node.js 24 LTS를 권장**하고, **Node.js 22 이상**이면 됩니다
(`package.json`의 `engines`는 22 이상 · Docker 이미지는 Node 24 · CI는 Node 22와 24 둘 다로 시험합니다 · `.nvmrc`는 24).

```bash
npm ci
npm run build && npm run --silent build --workspace @aas/web
node apps/api/dist/server.js      # 저장소 맨 위 폴더에서 실행합니다
```

저장소 맨 위 폴더에서 띄우면 `apps/web/dist`의 저작 화면을 같은 포트에서 내줍니다.
Docker 구성이 대신 정해 주던 값을 직접 줍니다.

| 항목 | 뜻 |
|---|---|
| `PORT` | 대기 포트(기본 8080). Docker의 `APP_PORT`에 해당합니다 |
| `DATABASE_URL` | PostgreSQL 연결 문자열 — 여럿이 쓸 때. TimescaleDB(Community Edition 또는 Apache-2 Edition)가 있으면 수집값 저장에 사용합니다(없어도 뜹니다) |
| `DATABASE_SCHEMA` | 한 DB를 나눠 쓸 때의 스키마 이름(선택) |
| `AAS_DATA_DIR` | `DATABASE_URL` 없이 혼자 쓸 때 파일을 남길 폴더. 둘 다 없으면 **메모리에만** 두어 끄면 사라집니다(기동 로그가 알립니다) |
| `AAS_HOST` | 묶을 주소를 직접 정합니다. 주면 위의 보호 모드(127.0.0.1) 판단을 건너뜁니다 |
| `WEB_ROOT` | 저작 화면 폴더를 다른 곳에서 내줄 때 |
| `SIMULATOR_PORT` | 「가상 PLC로 연결」을 누를 때 뜨는 시험용 OPC UA 서버의 포트(기본 14850) |

그 밖의 항목(`AAS_TOKEN` · `AAS_ALLOW_OPEN` · `AAS_LANG` 등)은 위 표와 같습니다.

## 운영

```bash
docker compose logs -f app     # 기동 로그 · 오류
docker compose ps              # 상태
docker compose down            # 내리기 (자료는 남습니다)
docker compose down -v         # 🔴 자료까지 삭제 — 되돌릴 수 없습니다
docker compose exec db psql -U aas -d aas   # DB 직접 접속
```

**살아 있는지 확인**: `curl http://localhost:8080/health` → `{"status":"ok","version":"2.4.0","auth":"on"}`

## 자료 백업 — 꼭 하십시오

AASX 파일과 수집값이 전부 DB에 있습니다. 컨테이너를 지워도 볼륨(`pgdata`)이 남지만, **디스크가 죽으면 끝입니다.**

```bash
# 백업
docker compose exec -T db pg_dump -U aas aas | gzip > aas-backup-$(date +%Y%m%d).sql.gz
# 복구
gunzip -c aas-backup-20260825.sql.gz | docker compose exec -T db psql -U aas -d aas
```

## 판 올리기

**먼저 알아 둘 것 — 폴더 이름이 곧 자료의 이름입니다.** Docker는 꾸러미를 푼 폴더 이름으로
자료(볼륨)를 찾습니다. 새 판을 다른 이름의 폴더에 풀어 그대로 띄우면 **빈 DB로 뜹니다**
(옛 자료는 지워지지 않고 옛 이름 아래 남아 있습니다). 그래서 새 폴더의 `.env`에 처음 설치한 이름을 적어 줍니다.

```bash
# ① 지금 쓰는 이름을 확인합니다 — 「<이름>_pgdata」의 <이름> 부분
docker volume ls | grep pgdata
#   local     vexplor-aas-studio-110-windows_pgdata

# ② 옛 판을 내립니다
cd VEXPLOR-AAS-Studio-2.4.0-windows && docker compose down && cd ..

# ③ 새 판을 풀고 설정을 가져옵니다
tar xzf VEXPLOR-AAS-Studio-1.2.0-windows.tar.gz
cd VEXPLOR-AAS-Studio-1.2.0-windows
cp ../VEXPLOR-AAS-Studio-2.4.0-windows/.env .
grep -q '^COMPOSE_PROJECT_NAME=' .env || echo 'COMPOSE_PROJECT_NAME=vexplor-aas-studio-110-windows' >> .env   # ①에서 본 이름

# ④ 띄웁니다
docker load -i images.tar.gz && docker compose up -d
```

윈도우·맥에서는 옛 폴더에서 `중지.bat` · `중지.command`로 내리고, 옛 `.env`를 새 폴더에 복사한 뒤
메모장·텍스트 편집기로 `COMPOSE_PROJECT_NAME=<①에서 본 이름>` 한 줄을 더하고, `설치.bat` · `설치.command`를
두 번 클릭합니다. 꾸러미 이름의 `-windows` · `-mac`은 처음 설치한 것과 같은 것을 받으십시오.

이렇게 하면 옛 자료(볼륨)를 그대로 다시 사용합니다. 띄운 뒤 화면에 옛 파일이 보이는지 꼭 확인하십시오. 판 번호는 화면 왼쪽 위 로고 옆과 `/health`에서 확인합니다.

DB 표 구조에는 **스키마 판 번호**가 따로 적혀 있어(`schema_version` 표), 새 프로그램이 옛 DB를
만나면 기동 때 스스로 올립니다(로그: `저장소: postgres · … · 스키마 N판`).
반대로 **되돌리기**(옛 꾸러미 + 새 DB)는 기동을 거부합니다 — 옛 프로그램이 새 표를 반쯤 읽고
자료를 잃는 것보다 멈추는 편이 낫기 때문입니다. 되돌려야 하면 백업한 DB를 함께 되돌리십시오.

## 🔴 인터넷에 열 때 — 읽고 결정하십시오

기본 구성은 **HTTP**입니다. 사내망에서는 문제없지만, 공인 IP로 열면:

- **토큰이 평문으로 흐릅니다.** 중간에서 가로채면 그대로 뚫립니다
- 공인 IP에 포트를 열면 자동 스캐너가 몇 시간 내로 찾아옵니다

꼭 열어야 한다면 **앞단에 HTTPS 리버스 프록시**(nginx·Caddy·Traefik)를 두고,
`AAS_PUBLIC_URL=https://실제주소`를 설정하십시오. 그게 어렵다면 **VPN이나 터널**(Tailscale 등)을
쓰는 편이 안전하고 설정도 간단합니다.

### Caddy 예시 — 가장 손이 적게 갑니다

인증서를 알아서 받고 갱신합니다. 서버에 Caddy를 설치하고 `Caddyfile` 한 장이면 됩니다.

```caddyfile
aas.사내도메인 {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
caddy run --config Caddyfile
```

그리고 `.env`를 이렇게 맞춥니다.

```bash
APP_PORT=8080
AAS_PUBLIC_URL=https://aas.사내도메인   # 레지스트리가 알려 줄 주소
```

- 공인 도메인이 없으면 `aas.사내도메인 { tls internal … }`로 자체 서명 인증서를 쓰고,
  사내 PC에 Caddy 루트 인증서를 한 번 설치합니다
- 프로그램은 프록시가 붙여 주는 `X-Forwarded-Proto`를 보고 **HTTPS일 때만**
  로그인 쿠키에 `Secure`를 붙이고 HSTS를 말합니다. 평문 서버가 HSTS를 말하면
  그 주소가 브라우저에서 영영 https로만 열리게 굳기 때문입니다
- 프록시를 쓰면 `docker-compose.yml`의 포트를 `127.0.0.1:8080:8080`으로 묶어
  바깥에서 8080으로 바로 들어오지 못하게 하는 편이 좋습니다

🔴 **nginx를 쓴다면 머리글 두 개를 꼭 넘기십시오.** nginx는 `proxy_pass` 기본값이
업스트림 주소라 `Host`가 `127.0.0.1:8080`으로 바뀌어 갑니다. 그러면 프로그램이
「다른 사이트에서 온 요청」으로 보아 **로그인한 사람의 모든 저장이 403**이 됩니다.

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host              $host;              # 또는 X-Forwarded-Host
    proxy_set_header X-Forwarded-Proto $scheme;            # 없으면 Secure 쿠키가 안 붙습니다
}
```

Caddy는 둘 다 알아서 넘기므로 따로 적을 것이 없습니다.
