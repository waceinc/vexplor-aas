## 1. 무엇을 어떻게 연결하나

| | 읽어 가는 주소 `GET /integrations/events` | 웹훅 | MQTT | 내보내기 (JSON · CSV) | OPC UA 서버 | Part 2 REST |
|---|---|---|---|---|---|---|
| **MES** | 모델 · 가동 사건, 아무 번호부터 다시 받기 | 상태 · 알람 · 계수 · 한계 · 연결 사건을 몇 초 안에 | 같은 사건을 토픽으로, 설비별 보존 상태 | 공정 계층(ISA-95 단계), 설비 마스터 | 구독으로 실시간 값 | 서브모델을 id 로 읽기 |
| **ERP** | `equipment.master.changed` 와 `changedKeys` | 같은 사건을 밀어 보냄 | — | 설비 마스터, ERP 자재번호가 붙은 BOM | — | — |
| **CMMS** | 알람 · 계수 사건 | 알람으로 작업 지시 열기 | — | 보전 계획(작업 계획), sha256 이 붙은 문서 목록 | — | — |
| **CMMS 계측값** | — | — | — | `GET /integrations/meters`(하루 한 번 읽기) | — | — |

**이 도구가 하지 않는 일** — 이 기능들을 전제로 연동 계획을 세우는 일이 없도록 미리 적습니다.

- MES · ERP · CMMS 에 **쓰지 않습니다.** 알릴 뿐이고, 무엇을 할지는 받는 시스템이 정합니다.
- 설비에 **명령을 보내지 않습니다.** OPC UA 서버는 읽기 전용이고 PLC 쓰기는 없습니다.
- **OEE 값을 계산하지 않습니다.** `oee-inputs` 는 가동 · 정지 · 알람 · 데이터 없음 시간과 계수기 증가량만 줍니다.
  가동률 · 성능 · 품질의 정의는 MES 가 정합니다.
- **비용을 다루지 않고**, 보전 주기 · 위치 · 단위를 **지어내지 않습니다.** 모델에 없는 값은 빈 값(`null`)으로 내보내고
  `missing` 에 이름을 적습니다.

### VEXPLOR Logic Studio

[VEXPLOR Logic Studio](https://wace.me/platform-logic-studio) Cloud는 AASX 파일 자체를 받습니다 — 설비 화면에 파일을
끌어 놓고, 미리 보기를 확인하고, 가져옵니다. 기종(Type) 파일과 설비(Instance) 파일을 나눠 받고, 같은 파일을 다시 놓아도
바뀌는 것이 없습니다. 이 연결에는 구독 · 내보내기 · 공장 설치가 필요 없습니다. 원격 수집기가 Logic Studio Cloud로
실시간 값을 보내는 연결은 준비 중이며 지금은 제공하지 않습니다.

## 2. 켜기

사건 기록과 읽어 가는 주소는 **늘 동작합니다** — 연동을 켜지 않아도 모델 변경은 모두 기록됩니다.
보내기(웹훅 · MQTT), 상태 판정, 마스터 데이터 알림은 `INTEGRATIONS=on` 일 때만 시작합니다.

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `INTEGRATIONS` | `off` | `on` 이면 상태 판정 · 마스터 데이터 알림 · 보내기를 시작합니다. `DEMO_MODE` 에서는 늘 꺼집니다 |
| `AAS_INTEGRATION_ALLOW` | 비어 있음 | **사설망** 또는 **암호화 없는 http · mqtt** 대상으로 허용할 CIDR · IP · 호스트 이름(쉼표로 나눔, 각각 `:포트` 를 붙일 수 있음). 여기 적은 포트는 원래 막힌 포트라도 허용됩니다 |
| `AAS_SECRET_KEY` | — | 무작위 32바이트의 base64. 웹훅 비밀값과 MQTT 비밀번호를 봉인합니다. **PostgreSQL 에서는 있어야** 구독을 만들 수 있습니다. 폴더 저장소는 `<AAS_DATA_DIR>/secret.key` 를 사용합니다 |
| `INTEGRATION_RETENTION_DAYS` | `30` | 사건 기록 보관 일수(기록 시각 기준). 성공한 보내기는 7일, 끝내 실패한 건은 30일 보관합니다 |
| `INTEGRATION_TIMEOUT_MS` | `10000` | 웹훅 한 번 시도의 전체 제한 시간. 1000~60000 사이로 맞춰집니다. DNS 조회는 이와 별도로 5초가 지나면 끊습니다 |
| `OPCUA_ALLOW_INSECURE` | 꺼짐 | `on` 이면 예전처럼 인증 없는 OPC UA 서버(9장) |
| `OPCUA_PKI_DIR` | `<AAS_DATA_DIR>/opcua-pki`, 없으면 `./opcua-pki` | OPC UA 인증서 저장소 |
| `INTEGRATION_PROXY` | — | `http://[사용자:비밀번호@]호스트:포트`. 외부 호스트 이름은 서버가 주소로 바꾸지 않고 **이름 그대로** 프록시로 보냅니다(HTTP CONNECT, TLS 는 종단 간에 이름으로 확인). 사내 이름(점 없음, `.local` · `.internal` · `.lan` · `.corp` · `.home.arpa`)과 사설 주소는 위 규칙대로 직접 연결합니다. 프록시로는 https 웹훅만 보냅니다 — MQTT 브로커는 직접 연결합니다(`INTEGRATION_NO_PROXY` 에 적으십시오). 이름을 주소로 바꾸는 쪽은 프록시이므로, 사내 주소로 풀리는 이름을 막는 일은 프록시 규칙이 맡아야 합니다 |
| `INTEGRATION_NO_PROXY` | — | 프록시가 있어도 직접 연결할 대상(`AAS_INTEGRATION_ALLOW` 와 같은 형식) |
| `OPCUA_CLIENT_PKI_DIR` | `<AAS_DATA_DIR>/opcua-client-pki`, 없으면 `./opcua-client-pki` | 수집할 때 쓰는 OPC UA 인증서 저장소. 보안 모드 · 정책 · 사용자 이름 필요 여부는 AID(AID 1.1 `securityDefinitions`)에서 가져옵니다. 처음 보는 서버 인증서는 거절하고 `rejected/` 에 두며, `trusted/certs` 로 옮기면 신뢰합니다 |
| `OPCUA_CLIENT_TRUST` | — | `first-use` 면 처음 본 서버 인증서를 받아들입니다 |
| `OPCUA_CLIENT_CREDENTIALS` | — | AID 가 사용자 이름을 요구하는 서버용 JSON 파일 `{ "<엔드포인트>": { "userName", "password" } }`. 비밀번호는 AAS 에 두지 않습니다 |
| `EDGE` | 비움 | 비우면 관리자가 화면 「설정 → 원격 수집기」에서 켭니다(그전엔 꺼짐). `on` 은 늘 켜짐, `off` 는 늘 꺼짐(docs/엣지설치.md) |
| `AAS_PUBLIC_URL` (기존) | — | 공개 주소. 넣으면 사건의 `dataschema`, 링크, 문서 주소가 절대 주소가 됩니다 |

```bash
# 마스터 키를 한 번 만들고 데이터베이스 백업과 함께 보관합니다
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Docker 는 `.env` 에 값을 넣으면(`.env.example` 참고) `docker-compose.yml` 이 그대로 전달합니다.

**연동 창** — 설정 메뉴 → **연동 (MES · ERP · CMMS)**.

| 누가 | 보는 것 |
|---|---|
| 관리자(로그인 세션) | 상태 · 보내기 구독(보낸 기록 포함) · 내보내기 · 준비 점검 · 판정 규칙 · 외부 번호 · OPC UA 인증서 |
| 편집자 | 읽어 가는 주소 · 내보내기 · 준비 점검 · 파일별 판정 규칙 · 외부 번호 (서버 공통 규칙은 읽기만) |
| 보기 전용 계정, 읽기 전용 API 키 | 읽어 가는 주소 · 내보내기 · 준비 점검 |

구독은 **관리자 로그인 세션에서만** 만듭니다 — API 키로도, 계정이 없는 열린 서버에서도 만들 수 없습니다(먼저 첫 관리자를
만드십시오). 열린 서버가 밖으로 연결을 만들 수 있으면, 같은 망의 누구든 그 서버를 원하는 곳으로 요청을 보내는 중계기로 악용할 수 있기
때문입니다.

## 3. 식별자와 연결 키

**연결 키는 `globalAssetId` 입니다.** 가동 · 마스터 데이터 사건에는 모두 `asset` 묶음이 붙습니다.

```json
"asset": {
  "globalAssetId": "https://example.com/ids/asset/press-03",
  "aasId": "https://example.com/ids/aas/press-03",
  "packageId": "pkg_12",
  "assetKind": "Instance",
  "serialNumber": "SN-2024-00317",
  "specificAssetIds": [ { "name": "mesResourceId", "value": "PRS-03" } ],
  "externalRefs": [ { "system": "mes:changwon", "type": "equipmentCode", "id": "PRS-03" } ],
  "path": ["WACE", "Changwon", "Line-A", "Pressing", "Press-03"],
  "isa95": { "enterprise": "WACE", "site": "Changwon", "area": "Line-A", "workCenter": "Pressing", "workUnit": "Press-03" }
}
```

- `packageId` 는 내부 번호이고 **다시 올리면 바뀝니다** — 키로 저장하지 마십시오.
- **Instance 와 Type.** 실제 설비는 Instance 셸뿐입니다. Type 셸(설비 한 대가 아니라 형식)은 설비 마스터 내보내기에서
  빠지고, `includeTypes=1` 일 때만 표시를 달고 들어갑니다.
- `serialNumber` 는 DigitalNameplate 의 `SerialNumber`(semanticId `0112/2///61987#ABA951#009`, 없으면 idShort)에서 오고,
  없으면 `null` 입니다. 지어내지 않습니다.
- **specificAssetId 이름.** 설비의 다른 번호를 AAS 안에 넣을 때는 다음 이름을 쓰고, 발급한 시스템을 가리키는
  `externalSubjectId` 를 꼭 붙입니다: `serialNumber`, `erpAssetNumber`, `cmmsEquipmentId`, `mesResourceId`,
  `erpMaterialNumber`, `manufacturerPartId`.

### 외부 번호 — ERP · MES · CMMS 의 번호

사내 번호(SAP 설비번호, 기능 위치, 원가센터, 자재, iCube 코드 …)는 AASX **안이 아니라 옆에**, 파일마다 외부 번호
문서로 보관합니다. AASX 파일은 회사 밖(공급사 · 시험기관)으로 나가는데, 사내 번호까지 나가면 안 되기 때문입니다.

```json
{ "system": "sap-s4:PRD:100", "type": "equipment", "id": "10002345", "publish": true,
  "externalSubjectId": "https://sap.example.com/PRD/100" }
```

- `system` 에는 **테넌트 · 클라이언트까지** 적습니다(`sap-s4:PRD:100`, `icube:WACE`). `|` 는 쓸 수 없습니다.
- `(system, type, id)` 하나는 설비 **하나**에만 붙습니다. 다른 설비가 같은 번호를 쓰려 하면 409 와 함께 지금 그 번호를 가진 설비를 알려 줍니다.
- `publish: true` 인 번호는 셸의 `specificAssetIds` 에 `name = "<system>:<type>"` 으로 실립니다. 일반 편집과 같아서
  이력과 `model.shell.updated` 사건이 함께 남습니다. 공개를 끄면 다시 빠지고, 다른 specificAssetId 는 건드리지 않습니다.
- 외부 번호를 바꾼 것은 **되돌리기(↶)로 되돌릴 수 없고**, 그 파일의 되돌리기 목록도 비워집니다. 되돌리기는 모델만
  되돌리므로, 공개한 번호가 셸에서만 빠지고 외부 번호 문서에는 `publish: true` 가 남는 일이 생기기 때문입니다.
  되돌리려면 외부 번호를 다시 저장합니다.
- `type: costCenter`(대소문자와 무관하게 `costCenter` 로 저장됩니다)와 `sensitive: true` 인 번호는 공개 · 내보내기 · 사건
  어디에도 **나가지 않습니다.**
- **연동 → 외부 번호**에서 고치거나 CSV 로 넣습니다(열
  `globalAssetId,subjectKind,subjectKey,system,type,id,publish,sensitive,externalSubjectId`). 넣기는 늘 미리 보기부터 보여 주고,
  더하거나 고치기만 합니다 — 파일에 없는 번호를 지우지 않습니다. 같은 파일을 두 번 넣으면 두 번째에는 바뀌는 것이 없습니다. 줄 번호에서 머리글이 1번째 줄이고, 첫 데이터 줄은 2번째 줄입니다.
  적용할 때 오류나 충돌이 남아 있으면 통째로 거절합니다(422 `ImportRejected`, 같은 보고, 바뀐 것 없음).
- 외부 번호가 있는 파일을 지우면 먼저 묻고, 연동된 시스템에는 `equipment.master.changed` 의 `operation: "removed"`
  (ERP 의 「폐기」 신호)가 갑니다.

### 찾기 순서

1. 셸 찾기: `GET /api/v3.0/lookup/shells?assetIds=<{"name":"globalAssetId","value":"…"} 의 base64url>`
   (공개한 specificAssetId 로도 찾습니다. 예: `sap-s4:PRD:100:equipment`)
2. 레지스트리에서 디스크립터를 읽고 **주소는 디스크립터에 적힌 것을 사용합니다** — 주소를 손으로 만들지 마십시오.
3. Part 2 로 서브모델을 읽습니다.
4. 바뀐 것은 구독(웹훅 · MQTT)으로 받거나 읽어 가는 주소로 가져갑니다.

찾기 대상은 AAS 안에 있는 것(공개한 외부 번호 포함)뿐입니다. 공개하지 않은 외부 번호로는 찾을 수 없습니다 — 찾기 결과와
AASX 내려받기 내용이 서로 달라지면 안 되기 때문입니다.

### 4.1 봉투 — CloudEvents 1.0, 구조화 JSON

```json
{
  "specversion": "1.0",
  "id": "evt_3K7Q9ZB2M4XH8V0TQW5N6R1JPC",
  "source": "urn:vexplor-aas:9f2c4e1a7b3d",
  "type": "kr.vexplor.aas.equipment.state.changed.v1",
  "time": "2026-10-14T01:41:07.300Z",
  "subject": "https://example.com/ids/asset/press-03",
  "datacontenttype": "application/json",
  "dataschema": "https://aas.plant.local/integrations/schemas/kr.vexplor.aas.equipment.state.changed.v1",
  "sequence": "00000000000000184223",
  "vxpackageid": "pkg_12",
  "vxrevision": 37,
  "vxcause": "edit",
  "vxchangeset": "chg_5f1d0c2e9a1b3c4d",
  "data": { }
}
```

| 항목 | 뜻 |
|---|---|
| `id` | 사건마다 다른 값 — **이것으로 중복을 거릅니다** (`webhook-id` 헤더와 같음) |
| `source` | `urn:vexplor-aas:<instanceId>` — 16진수 12자리, 서버를 다시 켜도 같음 |
| `subject` | 가동 · 마스터 데이터 사건은 `globalAssetId` 그대로, 모델 사건은 `packages/<id>/<shells\|submodels\|concept-descriptions>/<base64url id>` |
| `dataschema` | `AAS_PUBLIC_URL` 을 넣었을 때만 |
| `sequence` | 저장소 순번, 20자리로 0을 채움. 늘 커지지만 폴더 · PostgreSQL 저장소에서는 **빈 번호가 생길 수 있습니다** |
| `vxrevision` | 변경 뒤 파일의 개정 번호(모델 사건). `model.package.deleted` 는 마지막 개정 번호 + 1 |
| `vxcause` | `edit`, `fix`, `import`, `undo`, `redo`, `derivation`, `external-refs`, `seed`, `system` |

사건에는 **최소한의 정보만** 담깁니다: 식별자 · 개정 번호 · 바꾼 사람 · 링크만 있고 서브모델 내용은 없습니다. 내용은 Part 2
(`data.links.self`)나 `href` 에 적힌 내보내기로 다시 읽습니다.

### 4.3 순서 · 중복 · 보장

- 보내기는 **적어도 한 번**을 보장합니다. 받은 `id` 를 48시간 이상 기억해 두고 같은 것은 버리십시오.
- **보내는 순서는 보장하지 않습니다** — 받는 쪽 하나가 느려도 공장 전체가 멈추지 않게 하려는 것입니다. 사건마다
  `sequence`, `time`, (모델 사건) `vxrevision` 이 있으니, 파일 하나에서 이미 반영한 `vxrevision` 보다 크지 않은 모델 사건은 버리십시오.
- **읽어 가는 주소는 `sequence` 순서 그대로**입니다. 순서가 필요한 쪽은 이것을 사용합니다.
- 폴더 · PostgreSQL 저장소에서는 `sequence` 에 **빈 번호가 생길 수 있습니다** — 기록 도중 멈춘 사건은 무효로 처리하고(폴더),
  되돌린 트랜잭션이나 건너뛴 중복도 번호를 하나 차지합니다(PostgreSQL). **빈 번호는 데이터 유실이 아닙니다** — 이것 때문에
  경보를 내거나 다시 맞추지 마십시오. 읽어 가는 주소의 번호(`nextAfter`)로 계속 읽으면 확정된 사건은 하나도 빠지지 않습니다.
  늦게 확정되는 기록도 순서대로 받도록, 새로 생긴 빈 번호 뒤의 사건은 30초까지 기다렸다가 내줍니다.

## 5. 웹훅

웹훅 구독은 조건에 맞는 사건을 HTTPS 주소로 하나씩 POST 합니다. **연동 → 보내기 구독**(관리자)에서 이름, 주소,
받을 사건(목록에서 고르거나 `equipment.*` 같은 앞부분 — 하나 이상), 대상 파일(고르지 않으면 모두)을 정합니다.
**서명 비밀값은 한 번만 보여 줍니다** — 받는 쪽에 옮겨 적은 뒤 닫으십시오.

요청 하나의 형식:

```
POST /hooks/aas HTTP/1.1
content-type: application/cloudevents+json; charset=utf-8
user-agent: VEXPLOR-AAS-Webhook/<version>
webhook-id: evt_3K7Q9ZB2M4XH8V0TQW5N6R1JPC
webhook-timestamp: 1791942067
webhook-signature: v1,oMzirs96Lr/DagsIw2/eRtl0GRxBE78Ohcay8i9L7MQ=

{ …CloudEvent… }
```

### 5.1 서명 검증

`webhook-signature` = `v1,` + base64(HMAC-SHA256(키, `"{webhook-id}.{webhook-timestamp}.{받은 본문 그대로}"`)) 이고,
**키는 비밀값에서 `whsec_` 뒤를 base64 로 풀어낸 바이트**입니다. 비밀값을 바꾸는 동안에는 서명 두 개가 공백으로 나뉘어
오니, **하나라도** 맞으면 받아들입니다. 시각이 내 시계와 5분 넘게 다르면 거절하고, 비교는 고정 시간 비교로 합니다.
**받은 바이트 그대로** 서명을 계산하십시오 — JSON 을 다시 직렬화하면 바이트가 달라집니다.

시험값(내 코드가 맞는지 이것으로 확인합니다):

| | |
|---|---|
| secret | `whsec_dmV4cGxvci1hYXMtdGVzdC12ZWN0b3Ita2V5LTMyYiE=` |
| webhook-id | `evt_3K7Q9ZB2M4XH8V0TQW5N6R1JPC` |
| webhook-timestamp | `1791942067` |
| 본문 | `{"specversion":"1.0","type":"kr.vexplor.aas.integration.ping.v1"}` |
| webhook-signature | `v1,oMzirs96Lr/DagsIw2/eRtl0GRxBE78Ohcay8i9L7MQ=` |

**Node.js / TypeScript** (의존성 없음):

```js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verifyWebhook(secret, headers, rawBody, now = Date.now()) {
  const id = headers['webhook-id'];
  const timestamp = headers['webhook-timestamp'];
  const signatures = String(headers['webhook-signature'] ?? '').split(' ');
  if (!id || !timestamp || Math.abs(now / 1000 - Number(timestamp)) > 300) return false;
  const key = Buffer.from(secret.replace(/^whsec_/, ''), 'base64');
  const expected = createHmac('sha256', key).update(`${id}.${timestamp}.`).update(rawBody).digest();
  return signatures.some((item) => {
    const [version, value] = item.split(',');
    if (version !== 'v1' || !value) return false;
    const given = Buffer.from(value, 'base64');
    return given.length === expected.length && timingSafeEqual(given, expected);
  });
}
```

**Python 3**:

```python
import base64, hashlib, hmac, time

def verify_webhook(secret: str, headers: dict, raw_body: bytes, now: float | None = None) -> bool:
    msg_id = headers.get("webhook-id")
    timestamp = headers.get("webhook-timestamp")
    if not msg_id or not timestamp or abs((now or time.time()) - int(timestamp)) > 300:
        return False
    key = base64.b64decode(secret.removeprefix("whsec_"))
    expected = hmac.new(key, f"{msg_id}.{timestamp}.".encode() + raw_body, hashlib.sha256).digest()
    for item in headers.get("webhook-signature", "").split(" "):
        version, _, value = item.partition(",")
        if version == "v1" and hmac.compare_digest(base64.b64decode(value), expected):
            return True
    return False
```

Java · C# 코드는 영어판 [integration.md §5.1](integration.md#51-verifying-the-signature)에 있습니다(코드는 언어와 무관).
의존성 없는 받는 쪽 예제 전체는 `examples/webhook-receiver.mjs` 입니다 — 서명 두 개를 모두 확인하고, 오래된 시각을
거절하고, 48시간 동안 같은 id 를 거르고, 사건을 기록합니다.

### 5.2 응답 · 재시도 · 끝내 실패한 건

| 받는 쪽 응답 | 결과 |
|---|---|
| 2xx | 보냄 |
| 네트워크 · DNS · TLS 오류, 시간 초과, 408, 425, 429, 5xx | 다시 시도. `Retry-After` 헤더는 대기 시간을 **늘리기만** 합니다(그것과 정해진 간격 중 긴 쪽, 최대 1시간) |
| 그 밖의 4xx | 바로 끝내 실패 — 받는 쪽을 고친 뒤 다시 보냅니다 |
| 410 | 끝내 실패 **그리고** 구독이 꺼짐(「410 from receiver」) |
| 3xx | 실패 — 리다이렉트는 따라가지 않습니다 |

재시도 간격(12번, ±20 % 무작위 편차): 바로, 10초, 1분, 5분, 15분, 30분, 1시간, 2시간, 4시간, 8시간, 8시간, 8시간 —
주말 동안 MES 가 꺼져 있어도 재시도가 그 기간을 모두 덮습니다. 12번째도 실패하면 **끝내 실패**입니다. 끝내 실패가 50건 연달아 쌓이고
72시간 동안 성공이 없으면 구독을 끕니다. 구독을 스스로 지우지는 않습니다.

**연동 → 보내기 구독 → 보낸 기록**에서 시도별 응답 코드 · 오류 · 걸린 시간 · 실제로 연결한 주소를 보고, 끝내 실패한 건을
다시 보내거나(같은 사건 id — 받는 쪽이 중복으로 거릅니다), 어떤 번호부터 모두 다시 보낼 수 있습니다
(`POST /integrations/subscriptions/{id}/replay` 에 `{"fromSeq":"1000"}` 또는 `{"from":"<ISO 시각>"}`). 다시 보낼 수 있는
것은 성공했거나 끝내 실패한 건뿐이고, 기다리거나 보내는 중인 건은 409 `DeliveryBusy` 로 거절합니다.

**시험 보내기**는 서명한 `integration.ping.v1` 을 바로 보내고 응답 코드 · 걸린 시간 · 연결한 IP · 응답 앞부분 1KB 를
보여 줍니다. 사건 기록에는 남지 않습니다.

**비밀값 바꾸기**는 새 비밀값을 발급합니다. 24시간 동안은 옛 서명과 새 서명을 함께 보내므로, 그 사이에 받는 쪽을 바꾸면
사건을 놓치지 않습니다. 옛 비밀값이 아직 유효한 동안 다시 바꾸면 409 `RotationInProgress` 입니다.

## 6. MQTT

MQTT 구독은 브로커로 보냅니다(`mqtts://` 를 권합니다. `mqtt://` 는 허용 목록에 적힌 브로커만). 브로커 계정은 주소에
`user:password@` 로 적으면 서버가 주소에서 떼어 내 봉인해 보관합니다. 구독 주소의 스킴 · 호스트 · 포트를 바꾸면 새 주소에
`user:password@` 를 다시 적지 않는 한 **보관한 계정을 지웁니다** — 계정이 받은 적 없는 브로커로 넘어가지 않게 하려는 것입니다.

| 토픽 | 내용 | QoS · 보존 |
|---|---|---|
| `{prefix}/events/{kr.vexplor.aas. 를 뺀 종류}` 예: `vexplor/aas/9f2c4e1a7b3d/events/equipment.state.changed.v1` | CloudEvent 전체 | QoS 1, 보존 안 함. PUBACK 을 받으면 성공 |
| `{prefix}/equipment/{globalAssetId 의 base64url}/state` (「보존 상태」를 켰을 때만) | `{ "state", "since", "eventId" }` | QoS 1, **보존** — 나중에 접속한 쪽도 지금 상태를 바로 받음 |
| `{prefix}/status` | `{"online": true, "since"}`, 마지막 유언 `{"online": false}` | 보존 |

`prefix` 의 기본값은 `vexplor/aas/<instanceId>` 이고, `+` · `#` · NUL 을 쓸 수 없으며 200자 이하입니다.

**보안.** MQTT 3.1.1 에는 헤더가 없어 내용에 **서명이 없습니다.** `mqtts`(TLS)와, 이 서버만 그 토픽 아래에 발행할 수 있게
제한한 브로커 권한(ACL)으로 보호하십시오.

## 7. 내보내기

공통: `format=json|csv`(기본 json). CSV 는 RFC 4180(줄 끝 CRLF, 소수점 `.`, ISO 날짜, 수식 주입 방지 처리).
값이 여럿이면 `;` 로 붙이고, 값 안의 `;` 는 `\;` 로 적습니다. 선택: `bom=1` 은 UTF-8 BOM(엑셀용), `headers=keys|ko`
(**keys 가 약속된 열 이름**이고 `ko` 는 사람이 볼 머리글 — 요청 언어를 따르며 기본은 한국어, `lang=en` 이나 `Accept-Language` 면 영어), `meta=1` 은 첫 줄에 `#schema=…`, `lang` 은 여러 언어 값의
언어(기본 `ko`, 없으면 `en`, 그다음 첫 값). 고친 것이 없으면 두 번 내보내도 `exportedAt` 만 다릅니다.
화면에서는 **연동 → 내보내기**.

| `GET /integrations/exports/documents?packageId=` | `vexplor.documents/1` | 문서 × 판 × 파일마다 한 줄 |
| `GET /integrations/exports/bundle` | `vexplor.integrationBundle/1` | **위의 모든 내보내기를 zip 하나로** — §7.4. `packageId` 는 빼도 됨, JSON 만 |

### 7.1 고정된 CSV 열

열은 **끝에 더하기만** 합니다. 그 밖의 변경은 새 스키마 `/2` 입니다.

| 내보내기 | 열 |
|---|---|
| 설비 마스터 | `key, aasId, assetKind, typeAasId, packageId, revision, nameplate.manufacturer, nameplate.productDesignation, nameplate.productFamily, nameplate.modelNumber, nameplate.orderCode, nameplate.serialNumber, nameplate.yearOfConstruction, nameplate.dateOfManufacture, nameplate.productUri, nameplate.markings, physical.weight.value, physical.weight.unit, location.path, location.isa95.site, location.isa95.area, location.isa95.workCenter, specificAssetIds, externalRefs, missing, warnings` |
| BOM | `rootKey, parentPath, childPath, childName, childGlobalAssetId, quantity, level, entityType, erpMaterial, mapped` |
| 공정 계층 | `id, parentId, equipmentLevel, name, globalAssetId, aasId, packageId, serialNumber, quantity, specificAssetIds, warnings` |
| 보전 계획 | `maintenanceId, taskName, interval, intervalStatus, technicians, qualification, safety, stepSeq, stepId, stepName, instruction, durationValue, durationUnit, toolIds, consumableIds, documents, signatureRequired, sourceRef` |
| 문서 목록 | `documentId, documentDomainId, classId, className, classificationSystem, version, language, title, status, statusDate, issuer, fileName, contentType, size, sha256, available, url` |

칸 안의 형식: `specificAssetIds` = `name=value;…`, `externalRefs` = `system|type|id;…`, `location.path` 는 `/` 로 붙임.
BOM 의 `quantity` 는 하위 요소의 `BulkCount`(부모 하나당, 기본 1)이고, ERP 번호가 없는 줄도 `mapped=false` 로 남깁니다.
계층은 수량만큼 줄을 늘리지 않습니다. 공정 파일에서 설비의 수량이 1보다 크면 INT-4 경고이고, 설비 파일의 BOM 트리에서
수량은 부품 개수라 경고가 없습니다. 보전 계획의 `interval` 은 모델에 값과 단위가
분명히 있을 때만 채우고, 없으면 비우고 `intervalStatus: "missing"` 입니다. 문서 목록의 `url` 은 Part 2 첨부 주소
(`AAS_PUBLIC_URL` 이 있으면 절대 주소)이고, 파일이 없으면 `available=false` 에 `url` 은 비어 있습니다.

### 7.3 준비 점검

`GET /integrations/readiness[?packageId=]` 와 **연동 → 준비 점검**은 내보내기 결과를 틀리게 하거나 내보내기를 막는 문제를 보여 줍니다.
검사 지적이 아니므로 제출용 검증 결과서는 바뀌지 않습니다.

| Id | 정도 | 조건 | 결과 |
|---|---|---|---|
| INT-1 | 주의 | Type 셸에 DigitalNameplate `SerialNumber` 가 있음 | `includeTypes=1` 이 아니면 설비 마스터에서 빠짐 |
| INT-2 | 막힘 | 계층 맨 위 노드의 `globalAssetId` 가 셸의 것과 다름 | BOM 내보내기 거절(422 `BomRootMismatch`) |

| INT-4 | 주의 | 공정 파일에서 `BulkCount > 1` 인 계층 노드가 `globalAssetId` 하나를 가리킴 | 공정 계층 경고, 줄을 늘리지 않음 |
| INT-5 | 주의 | Instance 셸에 `SerialNumber` 가 없음 | `missing` 에 `nameplate.serialNumber` |

### 7.4 연동 묶음 — 파일 하나로 모두

받는 시스템(ERP · CMMS 가져오기 작업, VEXPLOR Logic Studio 테넌트)이 파일마다 다섯 번 호출하지 않고 한 번에 전체를
받을 때 사용합니다. 화면에서는 **연동 → 내보내기 → 전체 묶음(zip) 내려받기**.

```
manifest.json                          vexplor.integrationBundle/1
equipment.json                         vexplor.equipmentMaster/1 — Type 셸 포함(assetKind 로 구분)
packages/<packageId>/hierarchy.json    kr.vexplor.aas.hierarchy.v1
packages/<packageId>/bom.json          vexplor.bom/1
packages/<packageId>/maintenance.json  vexplor.maintenancePlan/1   (비어 있으면 넣지 않음)
packages/<packageId>/documents.json    vexplor.documents/1         (비어 있으면 넣지 않음)
```

- 각 파일은 단건 내보내기 주소가 주는 JSON 과 **똑같습니다** — 묶음은 담아 나르기만 하고 따로 계산하지 않습니다.
  모든 파일의 `exportedAt` 이 manifest 와 같고, 고친 것이 없으면 두 번 받아도 이 값만 다릅니다.
- `manifest.parts[]` 에 파일마다 `sha256` 과 항목 수가 있습니다 — 가져오기 전에 확인하십시오.
- 파일 때문에 거절된 내보내기(422 `NoHierarchy` · `NoBom` · `BomRootMismatch`)는 같은 코드와 문구로 `manifest.skipped[]` 에
  남습니다. 계층과 BOM 은 파일로 들어 있거나, 없으면 그 이유가 여기에 남습니다.
- 권한은 내보내기와 같습니다(읽기 권한, 작업 공간에 보이는 파일만). 문서 파일 자체는 zip 에 넣지 않고
  `documents.json` 에 내려받을 주소와 `sha256` 을 둡니다.

**서버 없이 — `@aas/bundle`.** AASX 를 직접 받는 제품(끌어 놓기)은 릴리스 꾸러미 `@aas/bundle` 의
`buildBundle(files, { exportedAt, lang })` 로 같은 묶음을 만듭니다. 이 API 의 내보내기 코드를 메모리 저장소 위에서 그대로
실행하므로, 같은 파일 · 같은 순서 · 같은 `exportedAt` 이면 zip 이 바이트까지 같습니다(`apps/api/test/integration-bundle-build.test.ts`
가 주소 결과와 대조합니다). 패키지 id 는 넣은 순서대로(`pkg_1`, `pkg_2`, …)이고, 문서 주소는 `publicBaseUrl` 을 주지 않으면
상대 주소입니다.

**서버 없이 읽을 목록 — `aidReadList`.** 같은 꾸러미의 `aidReadList(environment, packageId, intervalMs?)` 는 파일 하나의 AID
인터페이스를 원격 수집기가 읽을 태그로 풀어 줍니다(`docs/엣지계약.md` §4). 서버의 읽을 목록 코드 그대로이므로 같은
`packageId` 면 같은 `tagId` 가 나옵니다(`apps/api/test/edge-endpoints.test.ts` 가 엣지 끝점 결과와 대조합니다). AASX 로 자기
읽을 목록을 만드는 제품은 AID 해석기를 따로 짤 필요가 없습니다. 2.5.0 부터는 태그마다 힌트도 붙습니다 — 모델 요소의
`semanticId`, 제안 역할 `suggestedRole`(`run_state` · `counter` · `alarm_source` · `meter` · `condition` · `quality` · `value`),
같은 파일의 한계값 `limits`. 받는 쪽은 이 힌트로 역할과 규격 한계를 미리 채워 두고 사람이 확인하게 할 수 있습니다(`docs/엣지계약.md` §4.1).

**형식 연결(`typeAasId`).** Instance 행의 형식은 서버의 연결(「형식에 연결」)이 있으면 그것을, 없으면 셸 자체의 AAS
표준 `derivedFrom` 참조를 사용합니다. 「호기별로 나누기」가 적는 값이고 파일 안에 들어 있어 `buildBundle` 도 읽습니다. id 는
적힌 그대로이므로 형식이 다른 파일에 있거나 내보내지 않았을 수 있습니다. Type 행은 서버 연결이 없으면 null 입니다.

**견본.** `docs/examples/integration-bundle/` 에 AASX 4개(Type 1개, 그것으로 만든 Instance 2개, 두 설비를 라인에 놓은
회사 파일)와 그것으로 만든 묶음이 있습니다. 받는 쪽은 가져오기 시험을 이 견본으로 실행합니다. 견본과 코드가 어긋나면 위
시험이 실패합니다.

## 8. 가동 판정 규칙

가동 사건은 수집한 값([사용법.md](사용법.md) 8장)을 **서버의 규칙**으로 판정해 만듭니다. 화면의 하루 상태 막대도 같은
규칙으로 그리므로 막대와 사건의 결과가 항상 같습니다.

**서버 공통 규칙**(관리자, **연동 → 판정 규칙**): 가동 · 정지 · 알람 · 전원 꺼짐으로 볼 글자, 시간대(기본 `Asia/Seoul`),
하루 시작 시각(8시), 근무조(예: A 08:00–20:00, B 20:00–08:00). 규칙에 없는 값은 `unknown` 이며 정지로 짐작하지 않습니다.
상태 사건마다 `ruleSetHash` 가 붙어서, 받는 쪽이 어느 규칙으로 판정했는지 알 수 있습니다.

**파일별 규칙**(편집자): 상태 태그(하루 상태 막대에서 골라도 저장됨), 그 파일만의 판정 규칙(선택), 그리고 다음 규칙들.

| 규칙 | 동작 |
|---|---|
| 알람 | 태그가 참(true · 1 · 0 아닌 수)이거나 적어 둔 값과 같으면 켜짐. `raiseSamples` 번 연달아 켜져야 알리고, `clearSamples` 번 연달아 꺼져야 해제. 규칙마다 열린 알람은 하나이고, 열린 동안 다시 켜지면 `occurrences` 만 늘림. `code` · `text` 는 지정한 태그에서 오고 없으면 `null` |
| 계수기 | 주기마다 `to − from`. 값이 줄면 **`max` 를 정했을 때만** 한 바퀴 돈 것으로 봄(max 65535 에서 65530 → 4 = 10). 아니면 `reset: true, delta: null`. `maxRatePerHour` 를 넘는 증가는 `implausible`(`delta: null`). 직전 값이 신선도 창보다 오래되면 `gap: true` |
| 한계값 | `above`: 값이 한계를 `raiseSamples` 번 넘으면 넘음, 한계 − 여유 아래로 `clearSamples` 번 내려오면 되돌아옴(`below` 는 반대) |
| 보전 중 표시 | 그 태그가 참이면 사건은 그대로 보내되 `suppressed: true` 를 붙임 |
| 연결 | 연결 하나가 N주기 연달아 실패하면 `lost`(기본 2), 다음 성공에 `restored`. 품질 나쁜 태그만으로는 끊김이 아님 |

**판정 간격과 짧은 알람.** 값은 수집 간격마다 읽고, 사건의 `detectionResolutionMs` 가 그 간격입니다. 간격보다 짧은 알람은
두 번 읽는 사이에 놓칠 수 있습니다. 짧은 알람은 PLC 의 **누적 알람 횟수(줄지 않는 계수)**를 계수기 규칙으로 두면 한 번도
놓치지 않습니다.

**OEE 입력값** — `GET /integrations/equipment/oee-inputs?packageId=…&day=2026-10-14[&shift=A]` 는 가동 · 정지 · 알람 ·
전원 꺼짐 · 판정 못함 · 데이터 없음 시간(ms), `coverage`(값이 있던 비율), `resolutionMs`, 그리고 `produced` · `good` ·
`reject` 계수기 증가량을 줍니다. **OEE 값은 주지 않습니다** — 가동률 · 성능 · 품질은 계획 정지 · 이상 사이클 시간 같은
정의에 따라 달라지고, 그 정의는 MES 가 정합니다.

**상태 구간** — `GET /integrations/equipment/segments?packageId=…&from=…&to=…`(31일 이하).

**CMMS 계측값** — `GET /integrations/meters?packageId=…&counter=<id|runtime>&period=day` 는 기간마다 읽은 값 하나를
줍니다. `readingId` 가 항상 같은 값으로 만들어지므로 다시 넣어도 겹치지 않고, `evidence` 링크로 원래 값을 볼 수 있습니다.
`readingId` 는 읽은 값의 **수신 시각**으로 만들므로, 장비 시계가 멈춘 계수기도 기간마다 다른 id 를 받습니다.
`counter=runtime` 은 가동 · 정지 · 알람 · 꺼짐 · 판정 못함 초를 계산한 운전 시간입니다.

**이 세 조회의 한도** — 저장된 값을 읽으므로 한도가 있습니다. 한 요청이 값 200 000개를 넘게 읽으면 **422 `TooManyValues`**
(기간을 줄이십시오), meters 가 기간 1 000개를 넘으면 **422 `TooManyPeriods`**, 이런 조회가 동시에 2건을 넘으면
**503 `Busy`** 와 `Retry-After: 5` 입니다 — 적힌 초만큼 기다렸다가 다시 요청하십시오. 결과를 알리지 않고 잘라 보내는 일은 없습니다.

## 9. OPC UA 보안

`OPCUA_SERVER=on` 이면 **기본이 보안 연결**입니다.

- 보안 정책 `Basic256Sha256`, `Aes128_Sha256_RsaOaep`, `Aes256_Sha256_RsaPss`, 방식 `Sign` · `SignAndEncrypt`.
  `None` 접속점은 없습니다.
- **익명 접속은 받지 않습니다.** 이 도구의 **웹 계정**으로 로그인합니다(역할 무관 — 서버가 읽기 전용이므로).
  사용자 토큰은 **UserName** 만 받습니다 — X.509 사용자 인증서로는 로그인할 수 없습니다.
  잠긴 계정은 거절하고, 비밀번호를 여러 번 틀리면 웹 로그인처럼 늦춥니다.
- 계정이 하나도 없으면 OPC UA 서버는 **켜지지 않고**, 기동 로그에 이유를 남깁니다 — 먼저 첫 관리자를 만드십시오.
- `OPCUA_ALLOW_INSECURE=on` 이면 예전처럼 인증 없는 서버로 켜고 시작할 때 경고합니다. 외부와 분리된 시험망에서만 쓰십시오.

**클라이언트 인증서 믿기 (UaExpert 예)**

1. UaExpert 에 서버 `opc.tcp://<호스트>:<포트>/UA/AAS` 를 더하고 `Basic256Sha256 – SignAndEncrypt` 를 고른 뒤,
   사용자 이름 · 비밀번호에 웹 계정을 적습니다.
2. 첫 접속은 실패합니다 — 서버가 클라이언트 인증서를 「거절됨」에 넣었기 때문입니다.
3. **연동 → OPC UA 인증서**에서 지문을 UaExpert 가 보여 주는 지문(Settings → Manage Certificates)과 맞춰 본 뒤 **믿기**를 누릅니다.
4. 다시 접속합니다. UaExpert 가 서버 인증서를 믿을지 물으면 믿기를 고릅니다.

인증서 저장소는 `OPCUA_PKI_DIR`(기본 `<AAS_DATA_DIR>/opcua-pki`)입니다. Docker 에서는 폴더를 연결하고
`OPCUA_PKI_DIR` 로 가리키지 않으면 컨테이너 안에 있으므로, 다시 빌드하면 클라이언트 인증서를 다시 신뢰해야 합니다.

## 10. 네트워크 배치

```
 L4  ERP · CMMS (업무망)                  ◀── 내보내기, 읽어 가는 주소(HTTPS), DMZ 를 거친 L4 웹훅
 L3.5  DMZ / 리버스 프록시                ◀── 여기에 AAS_PUBLIC_URL 을 두고 TLS 를 끝냄
 L3  MES · 히스토리안 · VEXPLOR AAS Studio ◀── MES 로 웹훅 · MQTT, SCADA 용 OPC UA 서버
 L2  SCADA · HMI
 L1/L0  PLC · 설비                        ──▶ 이 도구가 수집(읽기만)
```

- 이 도구는 MES 옆 **3단계**에 둡니다. 아래 PLC 를 읽고 위로 알릴 뿐, 위에서 아래로 쓰는 일은 없습니다.
- DMZ 를 넘어 4단계로 갈 때는 **읽어 가기**(pull — 읽어 가는 주소, 내보내기)를 먼저 고릅니다. 업무망이 묻고 공장이 답하는 구조입니다.
  **밀어 보내기**(웹훅 · MQTT)는 3단계 안에서, 또는 DMZ 가 일부러 열어 둔 주소로만 사용합니다.
- 공장 안 대상(사설 주소, 암호화 없는 http, 내부 브로커)은 `AAS_INTEGRATION_ALLOW` 에 적어야 합니다.
- 폴더 저장소의 연동 보장은 **로컬 디스크**를 전제로 합니다. 네트워크 파일 시스템(SMB, NFS, NAS 동기화 폴더)은 이름 바꾸기 ·
  fsync 보장이 약하니 그런 곳에서는 PostgreSQL 을 쓰십시오.

## 12. 보안 원칙

- **누가 무엇을**: 구독 · 상태 · 서버 공통 규칙 · 인증서는 관리자 **로그인 세션**만(API 키 · 열린 서버 불가). 파일별 규칙과
  외부 번호는 편집자. 읽어 가는 주소와 내보내기는 읽기 권한이 있는 누구나, 다만 그 사람의 작업 공간에서 보이는 파일만.
  감사 사건은 관리자만 봅니다.
- **구독은 서버 전체에 적용됩니다.** 구독은 **모든 작업 공간**의 사건 중 조건에 맞는 것을 받습니다 — `AAS_WORKSPACE=private`
  서버에서도 그렇습니다. 작업 공간 분리는 읽어 가는 주소와 내보내기를 쓰는 사람에게 적용되고, 관리자가 만든 구독에는 적용되지
  않습니다. 한 고객의 데이터가 다른 시스템으로 가면 안 되는 경우에는 구독 대상을 해당 파일로 좁히십시오.
- **나가는 연결(SSRF) 제한**: 루프백 · 링크 로컬 · 멀티캐스트 · 브로드캐스트와 그 IPv6 표기는 항상 거절합니다. 사설 대역,
  특수 용도 대역(`192.0.0.0/24`, `192.0.2.0/24`, `198.18.0.0/15`, `198.51.100.0/24`, `203.0.113.0/24`, `2001:db8::/32`,
  `100::/64`, `2001::/23`, `64:ff9b:1::/48`, `::ffff:0:0:0/96`), 암호화 없는 http · mqtt 는 허용 목록에 있을 때만 허용합니다. 22, 25, 445, 502, 1433, 3306, 3389, 5432, 6379, 44818 같은 포트는
  허용 항목에 그 포트를 적지 않으면 거절합니다. DNS 는 시도마다 한 번 조회하고, 돌아온 주소를 모두 확인한 뒤 확인한 그 주소로만
  연결합니다(DNS 재바인딩 방지). 리다이렉트는 따라가지 않습니다.
- **비밀값**: 웹훅 비밀값과 MQTT 비밀번호는 마스터 키로 AES-256-GCM 봉인합니다. 목록 · 로그 · 보낸 기록 · 감사 사건 어디에도
  나오지 않고, 만들 때와 바꿀 때 한 번만 보여 줍니다. 감사 사건에서는 주소의 쿼리 값을 가립니다(`?token=***`) — 전체 주소는
  구독 조회(관리자)에서만 보입니다. 구독 응답에는 `Cache-Control: no-store` 가 붙습니다. 다른 `AAS_SECRET_KEY` 로 봉인된 비밀값이
  있으면 상태의 `masterKeyMismatch` 에 그 구독들이 나옵니다 — 원래 키를 되돌리거나 그 구독의 비밀값을 바꾸십시오.
- **내용 없는 사건**: 서브모델 내용은 사건으로 나가지 않습니다. 내용은 받는 쪽이 자기 권한으로 읽습니다.
- **체험 모드**: 연동은 항상 꺼져 있고, 밖으로 나가는 연결은 모두 거절합니다.

## 13. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 구독에서 「관리자를 먼저 만드십시오」 / 403 | 열린 서버이거나 API 키입니다. 관리자로 로그인하십시오(첫 관리자는 설정 메뉴에서 만듭니다) |
| 422 `TargetNotAllowed` | 사설 주소, 암호화 없는 http · mqtt, 막힌 포트입니다. `AAS_INTEGRATION_ALLOW` 에 호스트나 CIDR(필요하면 `:포트`)을 더하고 다시 시작 |
| 503 `MasterKeyMissing` | `AAS_SECRET_KEY` 없는 PostgreSQL 입니다. 키를 만들고(2장) 다시 시작 |
| 상태에 「다른 키로 봉인된 구독」이 나옴 | `AAS_SECRET_KEY` 가 바뀌었습니다. 예전 키를 되돌리거나, 그 구독의 비밀값을 바꾸고 받는 쪽도 고치십시오 |
| 503 `IntegrationsOff` | 그 기능은 백그라운드 작업이 켜져 있어야 합니다. `INTEGRATIONS=on` 으로 다시 시작 |
| 받는 쪽이 서명을 모두 거절 | 다시 직렬화한 본문으로 계산했거나, base64 를 풀지 않은 비밀값 글자를 키로 썼습니다. 시험값으로 확인 |
| 401 · 403 으로 끝내 실패 | 받는 쪽 인증이 이 서버의 요청을 막고 있습니다. 고친 뒤 「다시 보내기」 |
| 구독이 「410 from receiver」로 꺼짐 | 받는 쪽이 그 주소가 없어졌다고 응답했습니다. 주소를 고치고 다시 켜기 |
| 읽어 가는 주소가 410 Gone | 보관 기간보다 오래된 번호입니다. 전체를 내보내기로 받고 `oldestSeq` 부터 읽기 |
| 상태 사건이 없음 | `INTEGRATIONS` 가 꺼져 있거나, 파일에 상태 태그를 고르지 않았거나, 수집이 멈춰 있습니다 |
| `unknown` 이 많음 | 설비가 규칙에 없는 글자를 보냅니다. 연동 → 판정 규칙에 더하십시오 |
| BOM 내보내기 422 | INT-2 — 계층 맨 위 노드의 `globalAssetId` 를 셸의 것과 같게 고치십시오 |
| UaExpert 「BadSecurityChecksFailed」 | 인증서가 「거절됨」에 있습니다. 연동 → OPC UA 인증서에서 믿기 |
| OPC UA 서버가 켜지지 않음 | 계정이 없습니다. 첫 관리자를 만들고 다시 시작(시험망이면 `OPCUA_ALLOW_INSECURE=on`) |

## 14. 이번 판에서 바뀐 것

- **OPC UA 는 기본이 보안 연결입니다.** 클라이언트는 웹 계정으로 `Sign` 또는 `SignAndEncrypt` 방식으로 접속해야 하고,
  익명 접속과 `None` 정책은 없어졌습니다. 클라이언트를 옮기는 동안 예전처럼 쓰려면 `OPCUA_ALLOW_INSECURE=on` 을 두십시오.
- **찾기(discovery)에 `name` 이 필수입니다.** `GET /lookup/shells` 는 `name` 이 없는 자산 id 에 400 으로 응답하고,
  `globalAssetId` 로 찾으면 셸의 `globalAssetId` 만 비교합니다(전에는 값이 같은 specificAssetId 도 찾았습니다).
- **하루 상태 판정 규칙이 서버로 옮겨졌습니다.** 브라우저에만 있던 규칙은 관리자에게 한 번 「브라우저 규칙을 서버로
  옮기기」로 보여 주고, 그 뒤로는 모든 화면과 모든 상태 사건이 서버 규칙을 사용합니다.
- **연동 묶음.** `GET /integrations/exports/bundle`(화면: 연동 → 내보내기 → 전체 묶음 내려받기)이 보이는 파일의 모든
  내보내기를 목록(manifest)과 함께 zip 하나로 줍니다(§7.4).
- **다른 제품용 라이브러리.** `@aas/core` · `@aas/aasx` · `@aas/linter` 를 릴리스용으로 묶습니다
  (`scripts/pack-libraries.mjs`) — 릴리스 주소로 설치합니다(README 「다른 제품에서 라이브러리로 쓰기」).
- **원격 수집기(`EDGE=on`).** 엣지 규격 `vexplor.edge/1`(docs/엣지계약.md), 그 끝점과 관리 경로, 모의 엣지
  `scripts/mock-edge.mjs`.
- **수집할 때 OPC UA 보안.** 모드 · 정책 · 사용자 이름을 AID 1.1 `securityDefinitions` 에서 가져오고, 인증서 저장소 ·
  처음 본 인증서 신뢰 · 엔드포인트별 자격 증명은 `OPCUA_CLIENT_*` 로 정합니다.
- **프록시를 지나는 웹훅.** `INTEGRATION_PROXY` · `INTEGRATION_NO_PROXY` — HTTP CONNECT, 차단 규칙은 목적지 이름으로.
- **수집값에 중복 방지 키(데이터베이스 스키마 10판).** 같은 키로 다시 온 값은 한 번만 저장합니다 — PostgreSQL 은 시작할
  때 `value_key` 열과 유일 인덱스를 더하며, 키가 없는 값은 그대로입니다.
- **AID 통신 규약은 보조 의미 ID 로.** 인터페이스의 규약을 보조 의미 ID(AID 1.1)로 먼저 정하고, 다음은 엔드포인트 주소
  형식, 마지막으로 idShort 를 봅니다. BACnet 은 인식하지만 아직 수집하지 않습니다.
- **`derivedFrom` 으로 형식 연결.** 서버 연결이 없을 때 설비 마스터의 `typeAasId` 를 Instance 셸의 `derivedFrom` 에서
  채웁니다(전에는 파일로 올린 호기는 null 이었습니다). `typeAasId` 는 설비 사건의 비교값에 들어가므로, 그런 호기는 다음에
  다시 계산될 때 설비 변경 사건이 한 번 나갑니다.
- **서버 없이 묶음 만들기.** `@aas/bundle`(`buildBundle`)이 이 API 의 내보내기 코드로 AASX 에서 연동 묶음을 만듭니다.
  견본 묶음은 `docs/examples/integration-bundle/` 에 있습니다(§7.4).
- 새로 생긴 것: 사건 기록과 읽어 가는 주소, 웹훅 · MQTT 구독, 내보내기, 외부 번호, 준비 점검, 가동 판정 규칙, OEE 입력값, 계측값.
