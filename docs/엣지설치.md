# 원격 수집기(VEXPLOR Edge) 설치

*English: [edge-install.md](edge-install.md)* · 규격: [엣지계약.md](엣지계약.md)

VEXPLOR Edge 는 공장 안 PC 한 대에서 도는 프로그램 하나입니다. **서버에서 사람이 승인한 읽을 목록**에 있는 PLC · 제어기만
읽고, 서명한 묶음을 HTTPS 로 밖에 보냅니다. 읽기만 하고, 포트를 열지 않으며, 원격 정지가 없습니다. 같은 프로그램이 AAS
Studio 와 VEXPLOR Logic Studio Cloud 양쪽에 붙습니다.

## 1. 어디에 두나 — 배치 두 가지

| | A. DMZ · 사무망 | B. 설비망 |
|---|---|---|
| PC 위치 | 사무망과 설비망 사이, 양쪽에 닿는 자리 | 설비망 안, 서버로 나가는 길이 있는 자리(흔히 프록시 경유) |
| 설비 쪽 방화벽 | PC → PLC 포트(OPC UA 4840, Modbus 502, MQTT 1883/8883) | 새로 열 것 없음 |
| 바깥 쪽 방화벽 | PC → 서버 443(또는 프록시) | PC → 프록시(또는 서버 443) |
| PC 로 들어오는 연결 | **없음** | **없음** |

설비망에서 밖으로 나가는 길이 전혀 없으면 A, 설비망의 PC 한 대가 현장 프록시로 나갈 수 있으면 B 를 고릅니다. 두 경우 모두
안으로 들어오는 연결은 없습니다.

## 2. 연결하는 곳(전부)

| 목적지 | 이유 | 언제 |
|---|---|---|
| 설정의 서버 주소 443(또는 `proxy` 경유) | 읽을 목록 · 묶음 · 등록 | 늘 |
| 승인된 읽을 목록의 PLC 엔드포인트(OPC UA · Modbus TCP · MQTT) | 값 읽기 | 승인 뒤 |
| `update.manifestUrl` | 새 판 알림, 하루 한 번 | 설정했을 때만 |

이 밖의 연결은 없습니다. 시험이 모든 연결 시도를 기록해 이를 확인합니다(STD-009 T9).

## 3. 설치

`vexplor-edge-<판>-linux-x64.tar.gz` 또는 `-win-x64.zip` 을 받아 같은 릴리스의 `SHA256SUMS` 와 대조합니다.

```bash
sha256sum -c SHA256SUMS --ignore-missing            # Linux
Get-FileHash .\vexplor-edge-<판>-win-x64.zip        # Windows — SHA256SUMS 와 비교
```

서버에서 사람이 **등록 코드**를 만듭니다(`POST /edge/registration-codes`, 24시간 · 한 번만 유효).

**Linux**(systemd):

```bash
tar xzf vexplor-edge-<판>-linux-x64.tar.gz && cd vexplor-edge-<판>
sudo ./install.sh --server https://aas.example.com --code 7KQ4-M2XD-9PRT [--proxy http://proxy:3128] [--ca-file corp-ca.pem]
```

프로그램은 `/opt/vexplor-edge`, 설정은 `/etc/vexplor-edge/edge.json`, 키와 대기열은 `/var/lib/vexplor-edge`(서비스
계정만)에 둡니다. 서비스 `vexplor-edge` 는 권한을 줄인 상태로 돕니다(새 권한 없음, 시스템 읽기 전용, 상태 폴더만 쓰기, 특수
권한 없음). 기록: `journalctl -u vexplor-edge`.

**Windows**(관리자 PowerShell, 서비스는 WinSW 로 돕니다):

```powershell
Expand-Archive vexplor-edge-<판>-win-x64.zip; cd vexplor-edge-<판>-win-x64\vexplor-edge-<판>
.\install.ps1 -Server https://aas.example.com -Code 7KQ4-M2XD-9PRT [-Proxy http://proxy:3128] [-CaFile corp-ca.pem]
```

프로그램은 `C:\Program Files\VEXPLOR Edge`, 설정 · 키 · 대기열은 `C:\ProgramData\VEXPLOR Edge`(SYSTEM · Administrators ·
서비스 계정만)에 둡니다. 실행 파일은 아직 코드 서명이 없습니다 — `SHA256SUMS` 로 확인하십시오.

그다음 서버에서 장치를 **승인**합니다(`GET /edge/devices/:id/read-list-preview` 로 미리 보고 그 revision 으로 `POST …/approve`).
승인 전에는 아무것도 읽지 않습니다.

## 4. 비밀번호와 인증서

- **PLC 비밀번호**는 이 PC 의 자격 증명 파일에 엔드포인트별로 둡니다 — `{ "opc.tcp://10.0.0.5:4840": { "userName",
  "password" } }`, `--credentials-file` / `-CredentialsFile` 로 넘깁니다. AAS 와 읽을 목록에는 들어가지 않습니다.
- **OPC UA 인증서**: 수집기는 `<상태>/opcua-pki` 에 자기 인증서를 만듭니다. 처음 보는 서버 인증서는 거절하고
  `<상태>/opcua-pki/rejected` 에 두며, `trusted/certs` 로 옮기면 신뢰합니다(또는 `"opcua": { "trustFirstUse": true }`).
  OPC UA 서버도 수집기 인증서를 신뢰해야 합니다.

## 5. 운영

- 끊겨도 잃지 않습니다: 묶음은 `<상태>/queue` 에서 기다리다 서버가 다시 답하면 순서대로 나갑니다(각 묶음은 한 번만 저장).
  `maxQueuedBatches`(기본 100 000)를 넘거나 `maxQueueDays`(기본 30일)보다 오래되면 가장 오래된 것부터 버리고 그 수를
  보고합니다 — 소리 없이 버리지 않습니다.
- 서버가 형식 오류로 거절한 묶음은 사람이 볼 수 있게 `<상태>/refused` 로 옮깁니다.
- 해지된 장치는 스스로 보내기를 멈추고 대기열을 지킵니다. 스스로 다시 등록하지 않습니다.
- 새 판 알림(선택): `"update": { "manifestUrl": "https://…", "publicKey": "<릴리스 키>" }` 를 두면 서명이 맞는 새 판을
  기록과 다음 묶음의 상태에 알립니다. 내려받거나 설치하지 않습니다 — 새 꾸러미를 같은 설치 명령으로 설치하십시오.

## 6. 제거

Linux: `sudo systemctl disable --now vexplor-edge && sudo rm -r /opt/vexplor-edge /etc/vexplor-edge /etc/systemd/system/vexplor-edge.service`
(대기열이 더 필요 없으면 `/var/lib/vexplor-edge` 도). Windows: `vexplor-edge-service.exe stop`, `vexplor-edge-service.exe
uninstall` 뒤 두 폴더를 지웁니다. 서버에서도 장치를 해지하십시오.

## 7. 확인한 것

Linux 꾸러미는 이 안내대로 깨끗한 Ubuntu 24.04(x86_64)에 설치해 등록 · 승인 · 네트워크 너머 OPC UA 서버 값 송신까지
확인했습니다. Windows 꾸러미는 같은 방식으로 만들지만 **아직 Windows PC 에 설치해 보지 않았습니다**.
