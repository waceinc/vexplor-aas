# 현장 서버 설치 — AAS Studio + TimescaleDB + 원격 수집기 (Linux)

*English: [site-install.md](site-install.md)* · 수집기: [엣지설치.md](엣지설치.md) · 설정 전체: [설치.md](설치.md)

공장 서버 한 대에 AAS Studio 와 시계열 데이터베이스(TimescaleDB)를 명령 하나로 함께 올립니다. 원격 수집기(VEXPLOR Edge)도
같은 서버에 둘 수 있습니다. 설치 묶음 안에 프로그램 이미지가 들어 있어 인터넷 없이 설치됩니다. 설비 값은 공장 안에 쌓이고
오래된 값은 압축됩니다.

이 안내는 **Linux**(x86_64, systemd)를 다룹니다. **Windows 서버용 안내는 추후 제공합니다.**

## 1. 설치 묶음 두 판

| | 기본 묶음 `VEXPLOR-AAS-Studio-<판>-linux` | Community 묶음 `…-linux-community` |
|---|---|---|
| 데이터베이스 | **TimescaleDB Apache-2 Edition** (Apache 2.0) | **TimescaleDB Community Edition** (Timescale License) |
| 누구에게 | 모든 설치(무상 포함) | 제3자 소프트웨어 조항이 들어간 유상 사용권 계약 고객만 |
| 수집값 압축 | 없음 | 있음 — 실측 15~22분의 1 |
| 1분 · 1시간 집계 | 없음 | 있음 (`collected_value_1m` · `collected_value_1h`) |
| 보관 기간(오래된 값 지우기) | 있음 | 있음 |

두 판 모두 TimescaleDB 판을 하나로 고정합니다(지금 2.30.2). 묶음마다 `THIRD-PARTY-NOTICES.txt`, `licenses/` 의 라이선스
원문, 구성 목록을 적은 `BUNDLE.txt` 가 있고, 묶음 해시는 같은 릴리스의 `SHA256SUMS` 에 있습니다.

**Community 묶음을 쓰는 고객은** Timescale License 에 따라 AAS Studio 가 쓰는 데이터베이스의 스키마(표 · 열 · 인덱스 등)를
직접 만들거나 바꾸지 않습니다(조회는 됩니다). 이 데이터베이스를 AAS Studio 밖의 데이터베이스 제품이나 서비스로 쓰지
않습니다. 자세한 것은 묶음 첫 쪽 고지와 `licenses/TimescaleDB-TSL.txt` 에 있습니다.

## 2. 준비물

- Linux 서버(x86_64, systemd)와 Docker Engine · Compose 플러그인
  - Ubuntu: `sudo apt install docker.io docker-compose-v2`
  - 인터넷이 없는 서버는 이 패키지를 미리 받아 설치해 둡니다.
- 서버 사양
  - **확인한 최소**: 2 vCPU · 메모리 4 GB · 디스크 40 GB. 이 사양의 가상 서버에서 설치 · 재부팅 · 값 수집을 확인했습니다. 유휴 상태에서 AAS Studio 와 DB 를 합쳐 메모리 약 0.2 GB 를 사용합니다.
  - **태그 1 000개를 1초마다 읽는 공장**: 4 vCPU · 8 GB 이상과 SSD 를 권합니다. 이 값은 추정입니다 — 디스크는 아래 3절로 계산합니다.

## 3. 디스크 산정

하루 행 수 = 태그 수 × 86 400 ÷ 읽는 주기(초).

행 하나의 크기(실측: TimescaleDB 2.30.2, 태그 1 000개 · 1초 · 1시간 = 360만 행):

| | 행 하나 | 비고 |
|---|---|---|
| 원본(압축 전) | 약 320 바이트 | 인덱스 포함 |
| 압축 뒤 | 약 15 바이트 | Community 묶음만 |
| 1분 집계 | 태그 하나 · 1분에 약 170 바이트 | Community 묶음만, 기본 90일 |
| 1시간 집계 | 태그 하나 · 1시간에 약 230 바이트 | Community 묶음만, 계속 보관 |

필요한 디스크(보관 180일, 1시간 집계 3년, 여유 30% 포함):

| 공장 | 하루 원본 | Community — 7일 뒤 압축 | Community — 1일 뒤 압축 | 기본 묶음(압축 없음) |
|---|---|---|---|---|
| 태그 100 · 1초 | 2.6 GB | 약 53 GB | 약 34 GB | 약 600 GB |
| 태그 1 000 · 5초 | 5.1 GB | 약 134 GB | 약 95 GB | 약 1.2 TB |
| 태그 1 000 · 1초 | 25.7 GB | 약 532 GB | 약 341 GB | 약 6 TB |

- 실측은 사인파에 잡음을 더한 합성 값입니다. 값이 자주 바뀌지 않는 실제 설비는 더 많이 줄어듭니다.
- 기본 묶음은 압축이 없어, 보관 기간(`COLLECT_RETENTION_DAYS`)을 줄이거나 읽는 주기를 늘려 맞춥니다.

## 4. 설치

```bash
tar xzf VEXPLOR-AAS-Studio-<판>-linux.tar.gz          # Community 고객은 …-linux-community.tar.gz
cd VEXPLOR-AAS-Studio-<판>-linux
sudo ./install.sh                                      # AAS Studio + 데이터베이스
sudo ./install.sh --with-edge --edge-name "1라인"       # + 같은 서버의 원격 수집기
```

설치 스크립트가 하는 일:

1. Docker 를 확인하고 부팅 때 자동으로 켜지게 설정합니다.
2. 프로그램을 `/opt/vexplor-aas` 에 둡니다.
3. 설정 `.env` 를 만듭니다(관리자만 읽기). 데이터베이스 관리자 비밀번호, 앱 전용 계정, 비밀 키, 첫 관리자 코드를 새로 만듭니다.
4. 이미지를 불러와 실행하고, 서버가 응답할 때까지 기다립니다.
5. `--with-edge` 면 같은 서버의 AAS Studio 에 원격 수집기를 등록하고 서비스로 켭니다.

다른 옵션:

- `--port 8080` — 화면 포트
- `--dir /opt/vexplor-aas` — 설치 위치
- `--edge-credentials <파일>` — PLC 비밀번호 파일([수집기 설치 안내](https://github.com/waceinc/vexplor-edge/blob/main/docs/%EC%84%A4%EC%B9%98.md) 4절)

끝나면 화면에 주소와 첫 관리자 코드가 나옵니다. 원격 수집기는 서버에서 읽을 목록을 **사람이 승인한 뒤에만** 읽습니다.

## 5. 보안 기본값

- **데이터베이스 포트를 밖에 열지 않습니다.** AAS Studio 만 서버 안에서 연결합니다.
- **앱은 관리자가 아닌 전용 계정(`aas_app`)으로 연결합니다.** 이 계정은 자기 표만 소유합니다. 데이터베이스 관리자 비밀번호는 `.env` 에만 있고 화면 · 안내에 나오지 않습니다.
- **화면 · API 조작은 표 구조를 바꾸지 않습니다.** 표 구조는 서버가 시작할 때와 정해진 보관 작업 때만 바뀝니다.

## 6. 운영

| 할 일 | 명령 |
|---|---|
| 상태 | `cd /opt/vexplor-aas && sudo docker compose ps` |
| 기록 | `sudo docker compose logs -f app` — 첫 줄 「저장소」에 데이터베이스 판과 압축 · 집계 상태가 나옵니다 |
| 중지 · 다시 시작 | `sudo docker compose down` (자료는 남습니다) · `sudo docker compose up -d` |
| 새 판으로 올리기 | 새 묶음을 풀고 같은 명령(`sudo ./install.sh`) — `.env` 와 자료는 그대로 |
| 백업 | `sudo docker compose exec -T db pg_dump -U postgres -Fc aas > aas-$(date +%F).dump` |
| 원격 수집기 | `systemctl status vexplor-edge` · `journalctl -u vexplor-edge` |

재부팅하면 Docker, AAS Studio, 데이터베이스, 원격 수집기가 모두 자동으로 다시 시작됩니다.

보관 · 압축 · 집계 설정은 `/opt/vexplor-aas/.env` 에서 바꾸고 `sudo docker compose up -d` 로 반영합니다.

- `COLLECT_RETENTION_DAYS` — 보관 기간, 기본 180일
- `COLLECT_COMPRESS_AFTER_DAYS` — 압축까지 기간, 기본 7일
- `COLLECT_ROLLUPS` — 1분 · 1시간 집계 켜기
- `COLLECT_ROLLUP_MINUTE_DAYS` — 1분 집계 보관 기간, 기본 90일

각 설정의 뜻은 [설치.md](설치.md) 표에 있습니다.

## 7. 제거

```bash
cd /opt/vexplor-aas && sudo docker compose down -v      # -v: 자료도 지웁니다(되돌릴 수 없음)
sudo systemctl disable --now vexplor-edge                # 원격 수집기를 설치했다면 — 나머지는 수집기 설치 안내 6절
```

## 8. 확인한 것

깨끗한 Ubuntu 24.04 가상 서버(2 vCPU · 4 GB)에 Docker 만 설치한 뒤 안내대로 확인했습니다.

- `sudo ./install.sh --with-edge` 한 번으로 설치 · 수집기 등록까지 약 20초 걸렸습니다.
- 재부팅 뒤 모두 자동으로 다시 시작됐습니다.
- 승인한 뒤 네트워크 너머에 있는 PLC 모의기의 값이 저장됐습니다.
- 앱이 관리자가 아닌 계정으로 연결하고 데이터베이스 포트가 밖에 열려 있지 않음을 확인했습니다.
- 두 묶음 모두 확인했습니다. Community 묶음에서는 압축 · 집계 · 보관 작업이 앱 계정으로 실행됐습니다.

이 시험은 ARM 판 묶음으로 했습니다. x86_64 묶음은 같은 스크립트로 만듭니다.
