VEXPLOR AAS Studio는 AASX 작성 · 검사부터 설비 값 수집과 MES · ERP · CMMS 연동까지 웹 화면 하나로 처리합니다

VEXPLOR AAS Studio handles AASX authoring, validation, live collection and MES, ERP and CMMS integration in one web app

설비 AASX를 올리면 규칙 52종이 어긋난 곳을 짚고, 고칠 수 있는 지적은 미리 보고 한 번에 고칩니다. 같은 서버에서 IDTA Part 2 REST API로 AAS를 제공하고, OPC UA · Modbus TCP · MQTT로 설비 값을 모으고, S7 · MELSEC(MC 프로토콜) PLC는 바로 읽습니다. MES · ERP · CMMS에는 사건(이벤트)과 설비 정보를 보냅니다.

Upload a machine's AASX: 52 rules show what breaks, and the fixable findings are repaired in one step after a preview. The same server serves the AAS over the IDTA Part 2 REST API, collects machine values over OPC UA, Modbus TCP and MQTT, reads S7 and MELSEC (MC protocol) PLCs directly, and sends events and equipment data to MES, ERP and CMMS.

제조 IT · OT 엔지니어, MES · ERP · CMMS 연동 담당자, AAS 제출을 준비하는 기업이 직접 설치해 쓰는 오픈소스입니다.

Built for manufacturing IT/OT engineers, MES · ERP · CMMS integrators and teams preparing AAS submissions — self-hosted.

01작성 · 트리Author & tree

트리 화면은 AASX 구조를 펼쳐 보여 주고, 사용자는 그 화면에서 바로 값을 고칩니다

The tree shows the whole AASX, and you edit values in place

  • AASX(JSON · XML)를 열어 AAS → 서브모델 → 요소 순서로 봅니다Open AASX (JSON or XML) and browse AAS → submodel → element
  • 값 · 요소 · 서브모델 · ConceptDescription을 고치고, 값 표나 CSV 설비 대장으로 여러 값을 한 번에 채웁니다Edit values, elements, submodels and concept descriptions; fill many values at once from a value table or a CSV equipment list
  • 한 번에 되돌리고, 서브모델을 지난 시점으로 복원합니다One-step undo, and restore a submodel to an earlier point
  • 파일이 없으면 「견본으로 시작하기」가 다 채운 설비 1종과 공정 구성을 엽니다No file yet? "Start with a sample" opens a fully filled machine and a process structure

02검사 · 자동 고치기Findings & auto-fix

규칙 52종이 어긋난 곳을 짚고, 고치기 전에 바뀔 값을 먼저 보여 줍니다

52 rules point to what breaks and show each change before it applies

  • 패키지 구조(L1) · 메타모델 제약(L2) · 제출처 사업 규칙(L3)으로 나눠 검사합니다Three layers: package structure (L1), metamodel constraints (L2), submission business rules (L3)
  • 파일의 버전(V3.0 · V3.1 · V3.2)에 맞춰 검사합니다. 제품 여권(DPP) 메타데이터는 규칙 DPP-1 ~ DPP-5가 검사합니다Checks follow the file's version (V3.0 · V3.1 · V3.2); rules DPP-1 – DPP-5 check product passport (DPP) metadata
  • 위반 · 경고 · 참고로 나누고, 왜 틀렸는지와 고치는 법을 함께 적습니다Errors, warnings and notes, each with the reason and how to fix it
  • 고칠 수 있는 지적(규칙 19종)은 전 / 후를 비교해 체크한 것만 반영합니다. 바꾼 내용은 이관 대장에 남습니다Fixable findings (19 rules) show before / after; only the checked ones apply, and every relocation is recorded

03현장 값 수집Live collection

서버가 AAS 안의 AID대로 설비 값을 모으고, 설비마다 하루 상태를 그립니다

The server collects machine values by the AID inside the AAS and draws each machine's day

  • OPC UA · Modbus TCP · MQTT — 주소는 AAS 안의 AID(IDTA 02017) 서브모델이 정합니다OPC UA, Modbus TCP and MQTT, addressed by the AID submodel (IDTA 02017) inside the AAS
  • 2.10.0부터 S7 · MELSEC(MC 프로토콜) PLC를 게이트웨이 없이 읽기만 합니다 — VEXPLOR 확장 바인딩이며, 실제 PLC 실측은 아직입니다From 2.10.0, S7 and MELSEC (MC protocol) PLCs are read without a gateway — read only, a VEXPLOR extension binding, not yet checked on real PLCs
  • 값마다 받는 중 · 끊김 · 값 없음을 보여 줍니다Each value shows whether it is live, stale or missing
  • 설비마다 하루 상태 막대(가동 · 정지 · 알람)를 그립니다Each machine gets a daily status bar (running · stopped · alarm)
  • 실물 PLC가 없으면 도구 안의 가상 PLC로 바로 시험합니다No PLC at hand? Test with the virtual PLC built into the tool

06MES · ERP · CMMS 연동MES · ERP · CMMS integration NEW 2.0

2.0부터 MES · ERP · CMMS가 설비 사건과 설비 정보를 받아 갑니다

New in 2.0: MES, ERP and CMMS receive equipment events and master data

  • 읽어 가는 주소(pull feed) — 모든 변경과 가동 사건을 CloudEvents 1.0으로 순서대로 제공하고, 원하는 번호부터 다시 읽을 수 있습니다Pull feed — every model change and runtime event as CloudEvents 1.0, totally ordered, resumable from any cursor
  • 서명 웹훅 — HMAC-SHA256으로 서명합니다. 실패하면 다시 보내고, 끝내 실패한 건은 따로 남깁니다Signed webhooks — HMAC-SHA256 signatures, retries, and dead letters kept for replay
  • MQTT — 같은 사건을 토픽으로 보내고, 설비별 현재 상태는 retained 메시지로 남깁니다MQTT — the same events on topics, with each machine's current state retained
  • 판정 규칙 — 수집한 값으로 가동 상태 · 알람 · 계수기 · 한계값 사건을 만듭니다Runtime rules — state, alarm, counter and threshold events from collected values
  • 내보내기 — 설비 마스터 · BOM · 공정 계층 · 보전 계획 · 문서 목록을 JSON · CSV로Exports — equipment master, BOM, hierarchy, maintenance plan and documents as JSON or CSV
  • 외부 번호 — ERP · MES · CMMS 번호는 AASX 안에 넣지 않고 별도로 보관합니다External references — ERP, MES and CMMS numbers are kept next to the AASX, not inside it

연동은 INTEGRATIONS=on으로 켭니다(기본은 꺼짐). PostgreSQL에서 구독을 만들려면 AAS_SECRET_KEY도 필요합니다. 체험 서버에서는 항상 꺼져 있습니다.

Integrations are off by default — turn them on with INTEGRATIONS=on. Creating subscriptions on PostgreSQL also needs AAS_SECRET_KEY. They are always off on the trial server.

관리자 · 편집자 · 열람자. 누가 무엇을 고쳤는지 변경 이력에 남습니다.Admin, editor, viewer — with an audit trail of who changed what.
접속 범위Who can reach it
소스로 실행하고 계정도 API 키도 없으면 127.0.0.1에서만 접속됩니다. Docker 예시는 .env.example의 AAS_ALLOW_OPEN=1 설정 때문에 같은 망에 열립니다. 그래서 띄운 직후 첫 관리자를 만들고 앞단에 HTTPS를 둡니다.Run from source with neither accounts nor an API key and it listens on 127.0.0.1 only. The Docker example opens it to your network (AAS_ALLOW_OPEN=1 in .env.example), so create the first administrator right after start and put HTTPS in front.
OPC UA 서버OPC UA server
기본은 꺼져 있습니다. 켜면 웹 계정으로 로그인하며, Sign · SignAndEncrypt 연결만 받습니다. 익명 접속은 받지 않고, 클라이언트 인증서는 관리자가 한 번 신뢰 처리합니다.Off by default. When on, clients sign in with a web account over Sign or SignAndEncrypt; no anonymous sessions, and an administrator trusts each client certificate once.
개인 작업 공간Private workspaces
AAS_WORKSPACE=private로 설정하면 각자 자기가 올린 파일만 봅니다.AAS_WORKSPACE=private shows each person only what they uploaded.
로그인 보호Sign-in protection
비밀번호는 scrypt 해시만 저장하고, 5회 실패하면 5분 동안 잠깁니다. 쿠키는 HttpOnly · SameSite=Strict입니다.Only scrypt hashes are stored; five failures lock the account for five minutes. Cookies are HttpOnly and SameSite=Strict.
밖으로 나가는 연결Outbound connections
웹훅 · MQTT는 루프백 · 메타데이터 주소를 거부하고, 사설망은 허용 목록에 적은 곳으로만 보냅니다. 서명 비밀값은 AES-256-GCM으로 암호화해 보관합니다.Webhooks and MQTT refuse loopback and metadata addresses; private networks only when listed. Signing secrets are sealed with AES-256-GCM.

한계Limits

VEXPLOR AAS Studio가 하지 않는 일과 알려진 제약

What VEXPLOR AAS Studio does not do, and known limitations

  • 합격 판정은 제출처 검증기가 합니다. 이 도구는 제출 전 사전 점검용입니다.The receiving validator decides acceptance. This tool is a pre-check.
  • MES · ERP · CMMS에 쓰지 않고 설비에 명령하지도 않습니다. OEE 숫자도 계산하지 않습니다(계산에 쓸 시간과 계수만 제공합니다).It never writes into MES, ERP or CMMS, never commands machines and never computes an OEE number (it gives the time and counter inputs).
  • 기본 설정은 공유라서 로그인한 사람은 모두 같은 파일을 봅니다. 개인 모드에서도 관리자와 API 키로는 모든 파일을 볼 수 있습니다.Shared by default: everyone who signs in sees the same files. Even in private mode, administrators and API keys see everything.
  • 세션을 서버 메모리에 두므로 서버를 다시 켜면 모두 로그아웃됩니다. 서버 1대 구성을 전제로 합니다.Sessions live in server memory: a restart signs everyone out, and one server instance is assumed.
  • 메일 발송 기능은 없습니다. 비밀번호를 잊으면 관리자가 재설정합니다.No e-mail is sent. If someone forgets a password, an administrator resets it.
  • 연동 구독은 서버 전체를 대상으로 합니다. 한 고객의 자료가 다른 시스템으로 넘어가면 안 될 때는 구독 범위를 파일 단위로 좁힙니다.Integration subscriptions cover the whole server; narrow a subscription to its files when one customer's data must not reach another system.
  • AAS 메타모델 V3.0 · V3.1 · V3.2 파일을 읽고, 세 버전 가운데 하나로 내려받습니다. 공식 검증기 aas-test-engines 1.0.3은 V3.0만 판정합니다. V3.1 · V3.2로 쓴 파일은 시험에서 공식 JSON 스키마(v3.1.2 · v3.2.0)로 대조하며, 공식 검증기의 판정은 아직 받지 않았습니다.Reads AAS metamodel V3.0 · V3.1 · V3.2 files and downloads as any of the three. The official validator aas-test-engines 1.0.3 checks V3.0 only; V3.1 · V3.2 output is checked in the tests against the official JSON schemas (v3.1.2 · v3.2.0) and has not been checked by an official validator.
  • Part 2 API는 위 범위만 구현돼 있고, V3.2에서 새로 생긴 엔드포인트는 404를 돌려줍니다.The Part 2 API covers the operations listed above; endpoints new in V3.2 answer 404.
  • S7 · MC는 읽기만 하는 VEXPLOR 확장 바인딩입니다. AID 1.1에 바인딩이 없어 다른 AID 도구는 이 인터페이스를 읽지 못합니다. 공개 형식대로 만든 시험용 서버로만 시험했고 실제 PLC 실측은 아직 없습니다(MELSEC iQ-F의 8진 X · Y는 FX5에서 확인이 필요합니다). 문자열은 1바이트 문자로만 읽습니다.S7 and MC are read-only VEXPLOR extension bindings. AID 1.1 has no binding for them, so other AID tools do not read these interfaces. They are tested against test servers built from the published formats only — not yet on real PLCs (MELSEC iQ-F's octal X / Y needs a check on an FX5). Strings are read as single-byte characters.
  • Windows 원격 수집기(VEXPLOR Edge 1.2.0)는 GitHub의 Windows 시험 환경에서 서비스 설치를 확인했고, 공장 PC 설치는 아직입니다. 실행 파일에 코드 서명이 없어 SHA256SUMS로 확인하며, Windows on ARM은 지원하지 않습니다.The Windows remote collector (VEXPLOR Edge 1.2.0) passed its service install test on GitHub's Windows runners and has not yet been installed on a factory PC. The executable is not code-signed — check it with SHA256SUMS — and Windows on ARM is not supported.

시작하기Get started

VEXPLOR AAS Studio는 Docker 명령 4줄로 실행됩니다

Four lines start VEXPLOR AAS Studio with Docker

Terminal
git clone https://github.com/waceinc/vexplor-aas.git && cd vexplor-aas
cp .env.example .env
sed -i.bak "s/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=$(openssl rand -hex 16)/" .env
docker compose up -d --build

셋째 줄은 비어 있는 데이터베이스 비밀번호(POSTGRES_PASSWORD)를 무작위 값으로 채웁니다. 이 값이 비어 있으면 Docker가 시작하지 않습니다.

Line three fills the empty database password (POSTGRES_PASSWORD) with a random value — Docker refuses to start while it is empty.

브라우저에서 http://localhost:8080을 열고 설정 → 첫 관리자 만들기로 들어갑니다. 이 서버는 같은 망에 열려 있으므로(AAS_ALLOW_OPEN=1) 첫 관리자를 만들 때 설치 코드를 묻습니다. 코드는 docker compose logs app | grep "설치 코드"로 확인합니다. 첫 관리자를 만들기 전까지는 같은 망의 누구나 이 서버를 열 수 있습니다.

Open http://localhost:8080 and go to Settings → Create the first administrator. The server is open to your network (AAS_ALLOW_OPEN=1), so it asks for a setup code, printed in the startup log: docker compose logs app | grep "설치 코드" (or grep "setup code" with AAS_LANG=en in .env). Until the first administrator exists, anyone on the network can open it.
